# 序盤フロー（ワイプダッシュ）機能仕様書

> **アーカイブ（廃止済み）**: 旧「序盤フロー」タブの仕様書。現在はプランタブ（`docs/プラン機能仕様書.md`）に置き換え済み。

> 対応ソース: `src/js/32-tab-wipeflow.js`

## 概要

ワイプ直後の序盤タスクとハイドアウト立ち上げを効率よく進めるためのフローチャートタブ。
「序盤タスク（API実データ）」＋「戦略メモ（手書きの並行要素）」の2部構成。

- タブ id: `wipeflow` / ラベル「序盤フロー」/ アイコン `sitemap`
- タブ位置: 先頭（トレーダー解放の左）。ワイプ開始時の起点として最初に見る想定。

## 序盤タスクの定義（ユーザー確定・2026-07-03）

**序盤タスク = 「後続タスクを開けるゲートタスク」かつ「Lv1〜15の間に受注できる」タスク。**

コード上の抽出条件（`earlyGateTasks` useMemo）：

1. `minPlayerLevel <= EARLY_TASK_MAX_LEVEL`（＝15。Lv1-15で受注可能）
2. **後続タスクを1つ以上開ける**（他タスクの `taskRequirements` に自分が含まれている＝ successor を持つ）
3. `前提チェーンの深さ <= EARLY_TASK_MAX_DEPTH`（＝3）

> **3.（深さ上限）を入れる理由**: `minPlayerLevel` は明示的なレベル制限のみで、多くのタスクは
> `minPlayerLevel` が低くても深い前提チェーンの先にある。「minPlayerLevel≤15」だけだと約218件（うち後続あり186件）に
> 膨れ、実際にはLv15までに到達できないタスクまで含む。前提の浅さ（≤3）を条件に足すことで、
> Debut / Gunsmith 1〜4 / Background Check / Supplier など「現実的にLv1-15で受注できるゲートタスク」約45件に絞る。
> 上限値 `EARLY_TASK_MAX_LEVEL` / `EARLY_TASK_MAX_DEPTH` は `eft-tool.html` 冒頭の定数で調整可能。

## 構成

### (1) 序盤タスク（動的・API実データ / タスク完了と連動・つながりでグループ化）

- **データ源**: `apiData.tasks`（読み込み済みの tarkov.dev タスク）。上記定義で `earlyGateTasks` に抽出。
- **付与情報**: `successorCount`（開く後続タスク数）、`depth`（前提の深さ・ソート用）。
- **並び順**: `minPlayerLevel` 昇順 → `depth` 昇順 → タスク名。
- **チェック連動**: 各タスクの丸ボタンは `completedTaskIds`（`eft_tool_v2`）と連動し、クリックで既存の `toggleComplete(task.id)` を呼ぶ。＝**タスク検索タブで完了にすればここもチェック済み**になり二重管理にならない（`toggleComplete` は前提の一括完了・進行中ボードへの後続追加・ジャーナル記録も従来どおり発火）。
- **「完了タスクも表示」チェック**（`wfGzShowDone` state・既定OFF）: OFFのとき完了済みを隠す。全グループ空なら「すべて完了」メッセージ。
- **APIデータ未取得時**: 進捗欄・タスクは出さずプレースホルダのみ。ヘッダー連番は「序盤」ラベルの青系（`.wf-num-gz`）で戦略メモ（黄）と区別。

#### つながりグループ（`earlyClusters` useMemo）

序盤タスク集合の**中で**前提↔後続の辺がある連結成分ごとにまとめる（＝つながっているタスクは同じグループに表示）。

- 序盤集合内の `taskRequirements` 辺だけを無向辺として張り、DFSで連結成分を求める。
- 成分内は `minPlayerLevel → depth → 名前` 順。成分同士は「最小レベル → メンバー数が多い順」。
- 各グループは `.wf-cluster` カード（ヘッダー `.wf-cluster-head`：link アイコン＋`グループ N`＋`Mタスク・Lv範囲・完了 x/M`）。
- 例: Prapor 連鎖（Shooting Cans→Debut→Luxurious Life→Background Check→…）、Mechanic/Gunsmith 連鎖、Skier 連鎖、Therapist 連鎖などが1グループにまとまる。

#### タスク1件の表示（`.wf-task`・**タスク検索と同じ見せ方**）

- ヘッダー行 `.wf-task-head`: 丸チェック（`.wf-check`）＋タスク名（`.wf-task-name`）＋**EXP をタイトル横**（`.task-exp`・`+N EXP`）＋トレーダー（`.wf-node-trader`）＋Lv（`.task-muted`）＋**マップバッジ**（`.wf-map-badge`・objectives のマップ名／無ければ「マップ指定なし」）＋右端に**「タスク検索へ」ボタン**（`.wf-task-go`・`setActiveTab('tasks')`＋`searchForTaskByName`）。
- 前提/後続は**タスク検索の「タスクツリー」と同一**（`.task-tree`：`前提タスク列（青 .task-chip）→ .task-tree-node → 解放されるタスク列（緑 .task-chip）`）。チップクリックでそのタスクをタスク検索へ。前提チップのトレーダー名は `taskById` から補完（`taskRequirements.task` は id/name のみのため）。
- 完了タスクは `.is-done`（薄緑・名前打ち消し線）。

> **マップ情報**は表示済み（`taskMapNames(task)`＝objectives の map 名を重複除去）。**マップでの絞り込みは今後の追加予定**（現状は表示のみ）。

### (2) 戦略メモ（静的・コード内定数 `WIPE_FLOW`）

タスク**以外**の並行要素（ハイドアウト・トレーダーLL・立ち回りのコツ・節目）。チェックは `eft_wipeflow_v1` に保存。

```js
WIPE_FLOW = [ { id, title, level, goal, steps:[ { id, kind, trader?, title, detail } ] }, ... ]
```

**ノード種別 `kind` → アイコン/色（`WF_KIND`）:**

| kind | icon | 色 | 用途 |
|---|---|---|---|
| `hideout` | `home` | `--info` | ハイドアウト施設 |
| `trader` | `chart-bar` | `--warn-text` | トレーダー解放/LL |
| `tip` | `star` | `--text-secondary` | 立ち回りのコツ |
| `milestone` | `flag` | `--state-ok` | 節目（例: フリマ解放）。ノードを緑で強調 |

現行フェーズ（初期データ）：

| # | フェーズ | レベル | ゴール |
|---|---|---|---|
| 1 | 並行で進める土台 | 序盤通して | タスク消化と並行して回す下地（Lv15フリマ解放の意識・収納・スキル・素材キープ）|
| 2 | ハイドアウト土台 | Lv15前後〜 | 進行を加速する施設を投資対効果順に立ち上げる |
| 3 | 中期の軸 | Lv15+ | ロイヤリティと金策を伸ばし装備・弾の選択肢を広げる |

> タスク行はここに置かない（重複するため）。序盤の**タスク**は上の (1) が実データで担う。
> 内容の追加・修正はコード内 `WIPE_FLOW` を編集。ステップ id を変えると既存の localStorage チェックとの対応が切れる。

### 進捗保存（localStorage）

- `eft_wipeflow_v1` — **戦略メモ**のチェック済みステップ id 配列（`wipeFlowDone` Set）。`toggleWipeFlow` でトグル＆保存、`resetWipeFlow`（confirm）で全消去。ボタンのラベルは「戦略メモをリセット」。
- 序盤タスクのチェックは `eft_tool_v2` の `completedTaskIds`（＝タスク検索と共有・上記参照）。

### 上部進捗バー

`.wf-progress` は **序盤タスク**の完了率（`completedTaskIds` ベース・`序盤タスク X/N（Y%）`）を表示。APIデータ未取得時はバーを出さずプレースホルダ文言のみ。

## スタイル

- カード `.section.wf-phase`／ヘッダー `.wf-phase-head`（連番 `.wf-phase-num` or `.wf-num-gz`）／ゴール行 `.wf-phase-goal`／スパイン `.wf-spine`（戦略メモのノード列・左縦線）。
- 序盤タスク: グループ `.wf-cluster`（`.wf-cluster-head` / `.wf-cluster-title` / `.wf-cluster-meta`）＋タスク `.wf-task`（`.wf-task-head` / `.wf-task-name` / `.wf-task-go` / `.wf-map-badge`）。前提後続チップはタスク検索と共通の `.task-tree` / `.task-chip` / `.task-tree-col` / `.tree-col-label` / `.task-tree-node`。
- 戦略メモのノードは `.wf-node`（`milestone` は `.is-milestone`＝緑強調）。丸チェック `.wf-check`。
- `style.css` の「フェーズ13: wipeflowタブ」ブロック。状態色は `--state-ok-*` / `--warn-*` / `--info` 変数（生hexなし）。アイコンは全て `<Icon>` SVG（絵文字不使用）。
