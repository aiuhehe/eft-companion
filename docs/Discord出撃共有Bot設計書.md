## 4. 共有データ（アプリでの作り方）

形式そのもの（JSON・フィールド・含めないもの・バージョン）は Bot §4。

### 4.4 マップ名の正規化

`maps[]` には、アプリの `RAID_MAPS` の名前に正規化したものだけを入れる（重複は除く）。

tarkov.dev のデータでは、同じマップの派生版が別のマップとして登録されており、目標によっては派生版だけが付いている（2026-11-10 時点の regular で約20件）。tarkov.dev のデータはそのまま受け取り、アプリ側で次のように変換する。

| tarkov.dev のマップ | 正規化後 |
|---|---|
| Night Factory・Infected Factory | `Factory` |
| Ground Zero 21+・Ground Zero（チュートリアル版） | `Ground Zero` |
| The Lab（暗い版）・Infected Lab | `The Lab` |

- 正規化は、出撃準備タブのマップでの絞り込みと共有データの作成で**同じ関数**を使う（実装済み・Issue #30: `normalizeRaidMapName` / `normalizeRaidMaps`・対応表 `RAID_MAP_ALIASES`・`00-constants.js`）。これにより、派生版だけが付いた目標も出撃準備タブに表示されるようになる。
- 取得したデータそのものは書き換えない（絞り込みと共有データ作成のときに正規化関数を通す）。
- `Icebreaker`・`The Labyrinth`・`Terminal` は派生版ではなく別のマップとして `RAID_MAPS` に加える。`RAID_MAPS` は次の13マップになる: Customs / Factory / Woods / Shoreline / Interchange / Reserve / Lighthouse / Streets of Tarkov / The Lab / Ground Zero / Icebreaker / The Labyrinth / Terminal。
- 「設置」以外でマップ指定が無い目標は「どのマップでもよい」扱い。「設置」はマップ指定が無くても、マップを選ばない限り表示しない。
- Bot は同じ13マップの一覧を持ち、一覧に無いマップ名はそのマップだけを無視する（Bot §4.4）。`RAID_MAPS` を変えたら Bot の一覧（`src/maps.ts`）も合わせる。

### 4.5 送り方

- `PUT /api/share` の本文として、**圧縮しない JSON そのもの**を送る（`Content-Type: application/json`）。
- アプリの「送る内容を確認」は、同じ JSON を `eft_raidshare_YYYY-MM-DD.json` として保存する（何が送られるかを本人が確かめられるように）。
- 作成は `buildRaidShareData()`（`src/js/09-raid-share.js`・実装済み・Issue #31）。自動送信・JSON 保存で共通に使う。「送る内容を確認」ボタンは設定タブ「Discord 連携」の「開発中（今だけ表示）」の枠にある（#32 で出撃準備タブから移した・完成したら消す）。細かい作り方は `docs/出撃準備機能仕様書.md`「送る内容を確認」。
- 実装上の補足: マップ未指定の目標は `maps: []` のまま送る（クエストアイテムも同じ）。撃破の `detail` は距離 0 を書かない。カスタムタスクのアイテムは候補から選んだ本物のID（Issue #43）で、#43 より前に手入力で保存された仮アイテムID（`custom_item_…`）だけは `itemId` に入れない。

## 11. 連携と自動送信（アプリ側）

Bot 側の流れ・API の一覧と応答・連携トークンの扱いは Bot §11。

### 11.1 連携の流れ

流れ全体（`/raid link` の返答・コードの有効期限・試行回数の上限・「アプリの設定を開く」ボタン）は Bot §11.1。アプリがすることは次のとおり。

**設定タブ「Discord 連携」での連携**
- 連携コードの入力欄と「連携」ボタンを出す。Discord の表示は「482 913」と3桁ずつ区切られているので、空白・全角数字を整えてから `POST /api/link { code }` を送る。
- 成功したら、応答の連携トークンと表示名を保存し、連携中の表示に切り替える。
- アプリの URL のハッシュ `#status` で設定タブが開く（Bot の「アプリの設定を開く」ボタンのリンク先）。ハッシュにコードなどは入らない。
- 「連携解除」ボタンで `DELETE /api/link` を送り、保存したトークンを消す。

**Bot の URL の持ち方**（2026-11-12）
- **入力させない。** アプリがビルド時に埋め込んだ定数 `DISCORD_BOT_URL` を使う。
- 値は GitHub の Actions シークレット `DISCORD_BOT_URL` に置き、**リポジトリのソースには書かない**。
- `.github/workflows/pages.yml` の Build ステップで環境変数として渡し、`build.sh` が `src/` のプレースホルダーを置き換えて `dist/` に出す。公開される JS には入る（ブラウザの通信からもどのみち見える）が、リポジトリには残らない。
- ローカルビルド（`file://` 版）は `DISCORD_BOT_URL=… ./build.sh` のように環境変数で渡す。空のまま作った場合は、設定タブに Bot の URL の入力欄を出す（予備）。

**保存先**: グローバルキー `eft_discord_link_v1`（トークン・ユーザー名・最終同期時刻。Bot の URL は定数なので保存しない）。Discord のユーザーはモードをまたいで同じなのでモード別にはしない。送る中身は現在のモードのもの。**全データバックアップには含めない**（トークンは解除するまで使えるため、バックアップファイルが人の手に渡るとなりすまして送れてしまう。復元後は連携し直す）。

### 11.2 自動送信

- **連携中のときだけ送る**（同期のオン/オフ設定は置かない・2026-11-12）。連携した時点で同期されていると考えるのが自然で、操作を増やさないため。公開アプリでも、連携していない利用者（Bot を使っていない人）からは何も送られない。
- 進行タスク・目標チェック・タスク完了が変わったら、**最後の変更から30秒待ってまとめて** `PUT /api/share` を送る。前回送った内容と同じなら送らない。
- 本文は `buildRaidShareData()` の結果そのもの（圧縮しない JSON）。
- アプリは設定タブと出撃準備タブに「最終同期日時: 2026年11月12日 14:32」を出す。
- 送信のタイミングは変更から30秒後の自動送信と、ヘッダーの即時同期ボタン（下記）。設定タブに「今すぐ送信」ボタンは置かない（2026-11-12）。結果は `PUT /api/share` の応答で分かり、アプリは次のように動く。メッセージは設定タブと出撃準備タブの同期状態の欄（最終同期時刻の横）に出し、次に送信が成功したら消す。
  - 204（成功）→ 最終同期時刻を更新する
  - 401（トークン無効・解除済み）→ 同期をオフにして「連携が解除されています」と出す
  - 413 / 422（大きすぎる・形式違い・対応していない `v`）→ 同期はオンのまま「アプリ（または Bot）を更新してください」と出す。アプリと Bot の一方だけが新しい形式に更新された場合に起きる。中身が変わるまで同じ内容は送り直さない（前回と同じ内容は送らないため、失敗を繰り返さない）
  - 429（送りすぎ）→ 応答の `Retry-After` の秒数だけ待ってから送り直す
  - 通信できない（Bot が止まっている・オフライン）→ 「同期できませんでした」と出し、次の変更のときにもう一度送る

**ヘッダーの即時同期ボタン（2026-11-12 決定・未実装・#33 と一緒に作る）**
- ヘッダー右の「APIデータ取得」ボタンを、連携中は **Discord との即時同期ボタン**に置き換える。出撃直前やマップを切り替えた後に、30秒待たずに送りたいときに押す。出撃準備タブだけでなくどのタブからでも押せる
- 「APIデータ取得」ボタンは**廃止**する。API データは起動時に読み込み、失敗しても利用者には直せないため（押すのは開発者だけ）
- **未連携のとき**: ヘッダーには何も出さない（ボタンの場所は空く）
- **API データを読み直したいとき**: ページをリロードする。次の文言を合わせて直す
  - 設定タブのゲームモードの補足「※ 変更後はAPIデータを再取得してください」→「※ 変更後はページをリロードしてください」
  - 取得失敗時のヘッダーのエラー「（時間をおいて「再取得」してください）」→「（時間をおいてページをリロードしてください）」
- **前回と同じ内容のとき**: いったん**押したら必ず送る**（内容を比べない）。「同じなら送らない」にするかは [#54](https://github.com/aiuhehe/eft-companion/issues/54) で検討（#33 の自動同期は前回送った内容を持つので、それを使えば追加の保存なしで比べられる）

### 11.3 API

→ Bot §11.3（エンドポイント一覧・応答・CORS・送信頻度と試行回数の上限・連携トークンの扱い）。アプリ側の決まりは次のとおり。

- `POST /api/link` が 429 を返したら、`Retry-After` の秒数を「しばらく待ってからもう一度お試しください（約N分）」のように出す。`Retry-After` が読めないとき（Bot が `Access-Control-Expose-Headers` を付けていないなど）は、待ち時間を出さずに「しばらく待ってから」とだけ出す。6桁の数字でない入力は Bot で数えないので、アプリ側で全角数字・空白を整えてから送る。

### 11.4 仲間のボード（アプリ側）

読み込み API（`GET /api/boards`・`GET /api/boards/:id`）の形と、誰が読めるかは Bot §11.4。

**入り方**
- Discord のボードの [地図で見る] ボタンから、GitHub Pages 版のアプリが `#board=<id>` 付きで開く。アプリはハッシュのボード ID を読み、出撃準備タブで仲間のボードを表示する。
- `file://` で使っている人は、出撃準備タブで参加中のボードを選ぶ（`GET /api/boards`）。

**再読み込み**: 出撃準備タブで仲間のボードを表示している間だけ、30秒ごとに `GET /api/boards/:id` を読み直す。

**画面（出撃準備タブの中）**
- 参加中のボードを選ぶと、出撃準備タブの目標一覧に仲間の目標が重なる。行ごとに誰の目標かを**メンバー別の色**で示す（色はボードの参加順で、Discord と同じ）。
- 並び・まとめ方は Discord のボードと同じ（Bot §7・§8）。合算はアプリ側で行う（アイテムアイコンなどの API データを使って、Discord より見やすく出す）。文字数の制限が無いので、省略せずに全部出す。
- マップを選ぶと、アプリのマップ画像も表示する。ピンの共有先がそのボードのサーバーなら、サーバーのピン（§11.5）も同じ地図に出る。

### 11.5 マップピンの共有（アプリ側）

サーバー単位で共有する考え方・誰が編集できるか・削除の保持期間・API は Bot §11.5。

**共有先のサーバー**
- 設定タブ「Discord 連携」で、ピンの共有先を1つ選ぶ（`GET /api/guilds`）。
- 共有先を選んでいないとき（連携していない利用者を含む）は、今までどおり各自のブラウザのピン（`eft_task_pins_v1`）だけを使う。

**画面**
- ピン詳細に「最終編集 @名前 11/11 14:32」を出す。
- 「最近削除したピン」から、削除から30日以内のピンを元に戻せる。

**座標の変換**: Bot とはアプリ標準のマップ画像（`eft_maps_v1` の幅・高さ）に対する比率（0〜1）でやりとりする。送るときに `x / width`、受け取ったときに `x × width` に変換する。

**同期のしかた**
- サーバーのピンは、個人のピンとは別のグローバルキー `eft_task_pins_shared_v1`・`eft_custom_items_shared_v1` に控えとして持つ。個人のピン（`eft_task_pins_v1`）は消さないので、共有をやめれば元のピンに戻る。
- 読み込み: マップタブか出撃準備タブを開いたとき、表示している間は5分ごと、自分が編集した直後に `GET /api/guilds/:gid/pins?since=<前回の時刻>` で変更分だけを取得する。
- 書き込み: 追加・編集・削除はまず控えに反映して画面に出し、すぐに `PUT` / `DELETE` を送る。送れなかった変更は送信待ちとして残し、次の読み込みのときに送り直す（通信できない間もピンの登録は続けられる）。
- メモ画像: ピンの登録時に、アプリで縮小済みの JPEG（長辺1280px）を `PUT /api/guilds/:gid/images/:id` で送る。表示時は連携トークン付きで取得し、IndexedDB（`eft_media`）にキャッシュする。
- 初めて共有先を選んだとき、個人のピンがあれば「今あるピン N件をこのサーバーに追加しますか？」と確認する。追加する場合、同じ目標の近く（比率で 0.01 以内）にすでにピンがあればそのピンは追加しない。
