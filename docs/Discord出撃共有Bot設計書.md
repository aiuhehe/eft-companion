## 4. 共有データ（アプリでの作り方）

形式そのもの（JSON・フィールド・含めないもの・バージョン）は Bot §4。

### 4.4 マップ名の正規化

`maps[]` には、アプリの `RAID_MAPS` の名前に正規化したものだけを入れる（重複は除く）。

tarkov.dev のデータでは、同じマップの派生版が別のマップとして登録されており、目標によっては派生版だけが付いている（2026-11-10 時点の regular で約20件）。tarkov.dev のデータはそのまま受け取り、アプリ側で次のように変換する。

| tarkov.dev のマップ | 正規化後 |
|---|---|
| Night Factory・Infected Factory | `Factory` |
| Ground Zero 21+・Ground Zero（チュートリアル版） | `Ground Zero` |
| The Lab（暗い版）・Infected Lab | `The Lab` |

- 正規化は、出撃準備タブのマップでの絞り込みと共有データの作成で**同じ関数**を使う（実装済み・Issue #30: `normalizeRaidMapName` / `normalizeRaidMaps`・対応表 `RAID_MAP_ALIASES`・`00-constants.js`）。これにより、派生版だけが付いた目標も出撃準備タブに表示されるようになる。
- 取得したデータそのものは書き換えない（絞り込みと共有データ作成のときに正規化関数を通す）。
- `Icebreaker`・`The Labyrinth`・`Terminal` は派生版ではなく別のマップとして `RAID_MAPS` に加える。`RAID_MAPS` は次の13マップになる: Customs / Factory / Woods / Shoreline / Interchange / Reserve / Lighthouse / Streets of Tarkov / The Lab / Ground Zero / Icebreaker / The Labyrinth / Terminal。
- 「設置」以外でマップ指定が無い目標は「どのマップでもよい」扱い。「設置」はマップ指定が無くても、マップを選ばない限り表示しない。
- Bot は同じ13マップの一覧を持ち、一覧に無いマップ名はそのマップだけを無視する（Bot §4.4）。`RAID_MAPS` を変えたら Bot の一覧（`src/maps.ts`）も合わせる。

### 4.5 送り方

- `PUT /api/share` の本文として、**圧縮しない JSON そのもの**を送る（`Content-Type: application/json`）。
- 作成は `buildRaidShareData()`（`src/js/09-raid-share.js`・実装済み・Issue #31）。自動送信で使う。開発中に置いていた「送る内容を確認」（JSON 保存）ボタンは 2026-11-13（#34）で削除した。細かい作り方は `docs/出撃準備機能仕様書.md`「送る内容を確認」。
- 実装上の補足: マップ未指定の目標は `maps: []` のまま送る（クエストアイテムも同じ）。撃破の `detail` は距離 0 を書かない。カスタムタスクのアイテムは候補から選んだ本物のID（Issue #43）で、#43 より前に手入力で保存された仮アイテムID（`custom_item_…`）だけは `itemId` に入れない。

## 11. 連携と自動送信（アプリ側）

Bot 側の流れ・API の一覧と応答・連携トークンの扱いは Bot §11。

### 11.1 連携の流れ

流れ全体（`/raid link` の返答・コードの有効期限・試行回数の上限・「アプリの設定を開く」ボタン）は Bot §11.1。アプリがすることは次のとおり。

**設定タブ「Discord 連携」での連携**
- 連携コードの入力欄と「連携」ボタンを出す。Discord の表示は「482 913」と3桁ずつ区切られているので、空白・全角数字を整えてから `POST /api/link { code }` を送る。
- 成功したら、応答の連携トークンと表示名を保存し、連携中の表示に切り替える。
- アプリの URL のハッシュ `#status` で設定タブが開く（Bot の「アプリの設定を開く」ボタンのリンク先）。ハッシュにコードなどは入らない。
- 「連携解除」ボタンで `DELETE /api/link` を送り、保存したトークンを消す。

**Bot の URL の持ち方**（2026-11-12）
- **入力させない。** アプリがビルド時に埋め込んだ定数 `DISCORD_BOT_URL` を使う。
- 値は GitHub の Actions シークレット `DISCORD_BOT_URL` に置き、**リポジトリのソースには書かない**。
- `.github/workflows/pages.yml` の Build ステップで環境変数として渡し、`build.sh` が `src/` のプレースホルダーを置き換えて `dist/` に出す。公開される JS には入る（ブラウザの通信からもどのみち見える）が、リポジトリには残らない。
- ローカルビルド（`file://` 版）は `DISCORD_BOT_URL=… ./build.sh` のように環境変数で渡す。空のまま作った場合は、設定タブに Bot の URL の入力欄を出す（予備）。

**保存先**: グローバルキー `eft_discord_link_v1`（トークン・ユーザー名・最終同期時刻。Bot の URL は定数なので保存しない）。Discord のユーザーはモードをまたいで同じなのでモード別にはしない。送る中身は現在のモードのもの。**全データバックアップには含めない**（トークンは解除するまで使えるため、バックアップファイルが人の手に渡るとなりすまして送れてしまう。復元後は連携し直す）。

### 11.2 自動送信

- **連携中のときだけ送る**（同期のオン/オフ設定は置かない・2026-11-12）。連携した時点で同期されていると考えるのが自然で、操作を増やさないため。公開アプリでも、連携していない利用者（Bot を使っていない人）からは何も送られない。
- 進行タスク・目標チェック・タスク完了が変わったら、**最後の変更から30秒待ってまとめて** `PUT /api/share` を送る。前回送った内容と同じなら送らない（実装済み・Issue #33）。
  - 比べるのは内容のハッシュ（`createdAt` を除いた JSON・16進32文字）。成功したときに `eft_discord_link_v1` の `lastShareHash`・`lastSentAt` に保存する。
  - ただし前回の送信から**6時間**たっていたら、同じ内容でも送る（Bot は6時間で共有データを消すので、消えた後に「同じだから送らない」にならないように）。
- 本文は `buildRaidShareData()` の結果そのもの（圧縮しない JSON）。
- **送るモードは PvP・PvE・今のシーズン（`season_current`）だけ**（2026-11-13・Issue #57）。今のシーズンの `mode` は全員同じ `season_current` なので、同じシーズンの人どうしでそろう。**過去のシーズン**（モードバーの「+ 新シーズン開始」で残したもの）を表示しているときは共有データを作らない（`raidShareData` = `null`）ので自動送信せず、ヘッダーの即時同期ボタンも押せない（ホバーで「過去のシーズンは Discord に送りません」）。
- アプリは設定タブと出撃準備タブに「最終同期日時: 2026年11月12日 14:32」を出す（共通の `DiscordSyncStatus`・出撃準備タブは「マップ選択」見出しの右・連携中だけ・実装済み・Issue #34）。
- 送信のタイミングは変更から30秒後の自動送信と、ヘッダーの即時同期ボタン（下記）。設定タブに「今すぐ送信」ボタンは置かない（2026-11-12）。結果は `PUT /api/share` の応答で分かり、アプリは次のように動く。メッセージは設定タブと出撃準備タブの同期状態の欄（最終同期時刻の横）に出し、次に送信が成功したら消す。
  - 204（成功）→ 最終同期時刻を更新する
  - 401（トークン無効・解除済み）→ このブラウザの連携情報を消して（未連携に戻す）「連携が解除されています」と出す
  - 413 / 422（大きすぎる・形式違い・対応していない `v`）→ 連携はそのまま「アプリ（または Bot）を更新してください」と出す。アプリと Bot の一方だけが新しい形式に更新された場合に起きる。中身が変わるまで同じ内容は送り直さない（前回と同じ内容は送らないため、失敗を繰り返さない）
  - 429（送りすぎ）→ 応答の `Retry-After` の秒数（読めなければ60秒）だけ待ってから送り直す。待っている間は即時同期ボタンを押せない
  - 通信できない（Bot が止まっている・オフライン）→ 「同期できませんでした」と出し、次の変更のときにもう一度送る

**ヘッダーの即時同期ボタン（2026-11-12・実装済み・Issue #33 / #54）**
- ヘッダー右の「APIデータ取得」ボタンを、連携中は **Discord との即時同期ボタン**に置き換える。出撃直前やマップを切り替えた後に、30秒待たずに送りたいときに押す。出撃準備タブだけでなくどのタブからでも押せる
- 「APIデータ取得」ボタンは**廃止**する。API データは起動時に読み込み、失敗しても利用者には直せないため（押すのは開発者だけ）
- **未連携のとき**: ヘッダーには何も出さない（ボタンの場所は空く）
- **API データを読み直したいとき**: ページをリロードする。次の文言を合わせて直す
  - 設定タブのゲームモードの補足「※ 変更後はAPIデータを再取得してください」→「※ 変更後はページをリロードしてください」
  - 取得失敗時のヘッダーのエラー「（時間をおいて「再取得」してください）」→「（時間をおいてページをリロードしてください）」
- **前回と同じ内容のとき**: **送らない**（2026-11-12・[#54](https://github.com/aiuhehe/eft-companion/issues/54)）。自動同期と同じハッシュ（と6時間の条件）で比べる。押したときは送らなくても送ったときと同じく「同期中…」（回転アイコン・押せない）を出し、最終同期日時を今にする。結果はボタンが押せたことと最終同期日時（ボタンの下の段に常に出す）が変わることで分かるので、「同期済み（変更なし）」「同期しました」のような結果の文言は出さない（2026-11-12）
- **連打したとき**: 押してから同期が終わるまで（送らなかったときも最低0.8秒）ボタンを `disabled` にし「同期中…」を出すので、押し込みを受け付けない。429 で送り直しを待っている間も押せず「待機中（N秒）」と残り秒数を出す
- 失敗のメッセージはボタンの左に出す（設定タブと同じ文言）

### 11.3 API

→ Bot §11.3（エンドポイント一覧・応答・CORS・送信頻度と試行回数の上限・連携トークンの扱い）。アプリ側の決まりは次のとおり。

- `POST /api/link` が 429 を返したら、`Retry-After` の秒数を「しばらく待ってからもう一度お試しください（約N分）」のように出す。`Retry-After` が読めないとき（Bot が `Access-Control-Expose-Headers` を付けていないなど）は、待ち時間を出さずに「しばらく待ってから」とだけ出す。6桁の数字でない入力は Bot で数えないので、アプリ側で全角数字・空白を整えてから送る。

### 11.4 仲間の目標（アプリ側・実装済み・Issue #35）

読み込み API（`GET /api/boards`・`GET /api/boards/:id`）の形と、誰が読めるかは Bot §11.4。画面の細かい動きは `docs/出撃準備機能仕様書.md`「4b. 仲間の目標」。

**参加者のボタン**: 出撃準備タブの「Customs での目標」の見出しのすぐ下（枠なし）に参加者を1人1つのボタン（色の四角・アバター・名前・最後に同期した時刻）で並べ、押すとその人を目標一覧に出す／外す（複数選べる・2026-11-14）。1レイドだけ休む仲間を外して見られるようにするため。外した人は `eft_discord_link_v1.hiddenMembers` に保存。自分以外を1人でも出していれば目標一覧を合算した一覧にし、全員外せばふだんの自分の目標一覧に戻る。以前（2026-11-13）は「自分の目標だけ」⇔「仲間の目標も表示」の2択の切り替え（`hideFriends`）だったが、参加者ごとに選べるほうがわかりやすいので置き換えた。

**入り方**
- Discord のボードの [地図で見る] ボタンから、GitHub Pages 版のアプリが `#board=<id>` 付きで開く。アプリはハッシュのボード ID（UUID の形のものだけ・`getBoardIdFromHash`・`08-pre-app.js`）を読み、出撃準備タブで仲間の目標を表示する。開いた後のハッシュは `#raid` に戻る。
- **参加中のボードを自動で開く**（2026-11-13）。出撃準備タブを開くと `GET /api/boards` を読み、参加中のボードを開く。1人が参加できるボードは1つ（Bot 側で保証・aiuhehe/tarkov-raid-bot#28）なので、一覧は0件か1件で、選ぶ操作は置かない。利用者にボード ID を意識させないため。`file://` で使っている人もリンク無しで見られる。ボードを開いていない間は一覧も30秒ごとに読み直し、後から始まったボードも自動で開く。
- 連携していない人には、ボードのリンクで開いたときだけ「設定タブで Discord と連携してください」を出す。それ以外は何も出さない。
- 開いたボードを最初に読めたとき、Discord のボードでマップが選ばれていればそのマップを選ぶ（自動で開いたときは、まだマップを選んでいない場合だけ）。
- どのボードを開いているかは保存しない（リロードしても自動で開き直すため）。

**再読み込み**: 出撃準備タブを表示していて、ブラウザのタブが表に出ている間だけ、30秒ごとに `GET /api/boards/:id` を読み直す（`useFriendBoard`・`09-friend-board.js`）。ボードを開いていない間は `GET /api/boards` を30秒ごとに読む（Bot §5.1 の見積もりの `GET /api/boards/:id` と同じ間隔で、どちらか一方だけ）。応答ごと: 401 は自動送信と同じく連携情報を消す／403（参加していない）・404（終了した）はそのボードを閉じて理由を出す（新しいボードに参加すれば次の一覧の読み直しで自動で開く）／通信できないときは前回の内容を出したまま次の30秒後に読む。

**画面（出撃準備タブの中）**
- ボードを開いていると、出撃準備タブの目標一覧の位置に、**出している参加者（自分を含む）の目標を合算した一覧**を出す。行ごとに誰の目標かを**メンバー別の色**（`--member-0`〜`--member-4` = 赤・青・緑・黄・紫。`colorIdx` = ボードの参加順で、Discord の 🟥🟦🟩🟨🟪 と同じ）の四角と各自の残り「×5」で示す。アプリ UI では絵文字を使わない。
- まとめ方は Discord のボードと同じ（Bot §7・§8。同じ目標を1行にまとめ、撃破は合計せず各自の残りを並べる）。マップ未選択ならマップ別の目標一覧（押すとそのマップを選ぶ・並びも Discord と同じ）。**マップ選択時の欄は自分の目標一覧と同じ6種類・同じ順**（持ち込む／収集（FIR）／設置／倒す／脱出／調査 → どのマップでもOK・2026-11-13）で、「共通の目標」の欄は作らない。共通の目標は各欄の先頭に、左のアクセント色の線と色の四角でわかるように出す。文字数の制限が無いので、省略せずに全部出す。
- 合算はアプリ側で行う（`09-raid-aggregate.js`）。Bot の `src/aggregate.ts` と**仕様だけをそろえ、コードは共有しない**（Bot §8.4）。Bot のテスト（`test/aggregate.test.ts`）の例をアプリの関数に流して同じ結果になることを確かめる。アプリの合算結果は、まとめる前の「誰の・どのタスクの・どの目標か」（`entries`）も持つ（Bot の Goal には無い・アプリだけ）。
- **1行は自分の目標一覧と同じ見た目**（2026-11-13）。`entries` のタスク ID・目標 ID を自分の API データと突き合わせ、自分の言語の名前・説明文・バッジ、タスク名のリンク（タスク詳細のポップアップ）とトレーダー、自分のピン、自分の進行タスクの目標ならチェックボックスを出す。引けない目標（仲間のカスタムタスクなど）だけ、共有された `label` での簡易表示。収集（FIR）は自分の目標と同じ表示切替（1列／2列／3列／非表示）、「どのマップでもOK」は折りたたみ。
- **自分の分は手元の共有データで合算する**（Bot に届いた内容ではなく）。チェックするとすぐ自分の色が消える。参加者のうち自分は、共有データの中身か連携時の名前で探す（API は自分の userId を返さない）。
- Discord のボードにある「共通のタスク（タスク「Debut」）」の行は出さない。Discord は文字数の都合で行ごとにタスク名を書けないための行で、アプリは各行の下にタスク名と誰のタスクかを出す。マップ別の一覧の「共通 N件」も共通の目標だけを数える（アプリだけの `commonGoals`）。
- 目標ごとのタスク ID は共有データで届く。自分の API データで引けないのは仲間のカスタムタスクだけで、その目標は共有された名前のまま「（カスタム）」を付けて出す。
- マップを選ぶと、アプリのマップ画像も表示する（自分のピンが無くても地図は出す）。地図には仲間が共有しているタスクのピンも出し（自分が登録したピンのうち、誰かに残っている目標の分）、右の一覧の番号の下に、その目標が残っている人の色の四角だけを縦に並べる（数は出さない・タスク名が長くても押し出されない）。同じボードの参加者のピンも同じ地図に重ねて出す（§11.5）。

### 11.5 マップピンの持ち寄り（アプリ側・実装済み・Issue #36）

各自のマップピンを、**同じ出撃ボードの仲間どうしで見せ合う**（2026-11-17 に方式を変更）。ピンの持ち主は登録した本人だけで、他人のピンは書き換えない。API（`PUT /api/pins`・`GET /api/boards/:id/pins`・`members[].pinsUpdatedAt`）・上限・保存期間は Bot §11.5・§12。以前の案（サーバー単位で1セットを誰でも編集・共有先のサーバーを選ぶ・最終編集者・30日間戻せる）は、誰の位置を正とするかがぶつかるためやめた。

コードは `src/js/09-friend-pins.js`（送る・読む・まとめる・隠す）と、`14-app-components.js`（App の中で呼ぶ・表示の部品）。

**送る（`useDiscordPinSync`）**
- 連携中は、自分のピン（`eft_task_pins_v1`）・登録タスク品の名前・マップ画像の基準が変わったら、**最後の変更から10秒後**に `PUT /api/pins` でピン一式を丸ごと送る。再配置やメモの入力を1回にまとめるため。前回送った内容と同じなら送らない（`eft_discord_link_v1` の `lastPinsHash`・`lastPinsSentAt`）。Bot はピンを期限で消さないので、共有データのような6時間ごとの送り直しはしない。連携し直したとき・連携が解けたときは `lastPinsHash` も消す（次の連携で送り直す）。
- ピンはモードをまたいで共通なので、どのモード（過去のシーズンも）でも送る。
- 本文は `buildPinsShareData()` で作る。
  - 座標は標準マップ画像（`eft_maps_v1` の幅・高さ）に対する比率（0〜1・小数5桁）。基準の無いマップ・`RAID_MAPS` に無いマップのピンは送らない。マップ名は `normalizeRaidMapName` を通す。
  - 登録タスク品は `custom: true` を付け、手元の登録データの名前と略称を送る（相手のブラウザに無いため）。
  - メモ画像・登録タスク品の画像は送らない（別の Issue で足す）。
  - **Bot の上限に合わせて送る前に止める**: ピン2000件・メモは先頭50字（UTF-16 の文字数・サロゲートペアの片割れは残さない）・必要アイテムは先頭1件・ほかの文字列500字。手元のピンはそのまま（メモや2件目以降のアイテムは自分の画面には残る）。マップタブのメモ入力欄の横に、連携中だけ「Discord の仲間に見せるのはメモの先頭50字と必要アイテム1件まで（画像は送りません）」と出す。
- 応答: 204 → `lastPinsHash` を更新／401 → 連携情報を消す（§11.2 と同じ）／413・422 → 「ピンを Discord に送れませんでした。アプリ（または Bot）を更新してください」（中身が変わるまで送り直さない）／429 → `Retry-After` 秒（読めなければ60秒）後に送り直す／通信できない → 「ピンを Discord に送れませんでした（次の変更のときに送り直します）」。メッセージはマップタブの地図の下に出す。ヘッダーの即時同期ボタンはピンを送らない（ピンは10秒後に自動で送られるため）。

**読む（`useFriendPins`）**
- 仲間のボードを開いている間（出撃準備タブに加えて**マップタブを表示している間も** `GET /api/boards/:id` を30秒ごとに読む）、`members[].pinsUpdatedAt` が前回読んだときから変わったときだけ `GET /api/boards/:id/pins` を読む。通信できなかったときは次の読み直しでもう一度読む。403・404（Bot がまだピンの API を持たない場合も）はピン無しとして扱う。
- 自分の分は Bot から読まず、手元のピンを使う（すぐ反映するため）。自分は §11.4 と同じく `findSelfMember` で探す。参加者のボタンで外した人のピンも出さない。

**まとめる（`mergeMapPins`）**
- 同じ目標（`taskId`・`objectiveId`）で近い位置（比率で `FRIEND_PIN_MERGE_DIST` = 0.02 以内・仮）のピンを1つにまとめる。自分のピンは1本ずつ（自分のピンどうしはまとめない）。
- 位置は、自分のピンがあれば自分の位置、無ければ仲間のピンの平均。
- まとめたピンは、自分のピンなら元のピンに `friendPins`（`[{ userId, colorIdx, pin }]`）を足したもの、仲間だけのピンなら `{ id:'fp_…', friendOnly: true, friendPins, … }`（座標はピクセルに戻す）。

**出す場所と見た目**
- **マップタブ**: ピンのアイコンの色は自分のピンと同じ（目標の種類の色）のまま変えず、**ピンの上に、そのピンを登録している人（自分を含む）の色の四角（`--member-0`〜`4`）を横に並べる**（`.map-pin-owners`・2026-11-17）。自分も仲間も同じ場所に登録していれば何もしなくてよいことが、四角の並びでわかる。仲間だけのピンには自分の色が無い。四角は仲間のピンがまとまっているときだけ出す（自分だけのピンには出さない）。仲間だけのピンは出すのは、ボードの誰か（自分を含む）にまだ残っている目標の分だけ（自分の進行タスクでなくてもよい）。地図の下に「ピンの上の色の四角は、そのピンを登録している人（自分を含む）です。仲間だけのピン（このマップ N件）は押すと「自分のピンとして保存」「隠す」ができます」と出す。
- **出撃準備タブの地図**（仲間の目標を出しているとき・§11.4）: 仲間だけのピンは点線の枠（持ち主の色）の番号で出す。出す条件は自分のピンと同じ（出している誰かに残っている目標だけ）。
- 吹き出し（マップタブ）と右の一覧（出撃準備タブ）には、まとまった仲間のピンを人ごとに「色の四角・名前・メモ・必要な鍵」で並べる（`FriendPinNotes`）。仲間のアイテムは、API のアイテムなら自分の言語の名前と画像を引き、登録タスク品は名前だけ（画像なし）で出す。

**自分のピンとして保存**（仲間だけのピンに出す・`saveFriendPinAsMine`）
- 位置・メモ（複数人なら重ならないものを「 / 」でつなぐ）・必要な鍵を自分のピン（`eft_task_pins_v1`）にコピーする。ボードが終わっても自分のピンとして残る。保存すると自分のピンができるので、そのピンに仲間のピンがまとまる。
- 登録タスク品は、同じ名前のものが自分の登録タスク品にあればそれを使い、無ければ画像なしで登録する。

**隠す**（仲間だけのピンに出す・`hideFriendPin`）
- 他人のピンは直せないので、自分の画面でだけ隠す。まとめたピンに入っている仲間のピンをすべて隠す。
- 保存先はグローバルキー `eft_friend_pins_hidden_v1`（`["<userId>/<pinId>", …]`）。ボードやモードをまたいで同じ。全データバックアップに含める。マップタブの地図の下の「隠したピン N件を元に戻す」で全部戻す。
