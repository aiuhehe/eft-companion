# ステータス・設定 機能 — 機能詳細・実装仕様

> 対応ソース: `src/js/20-tab-status.js`・`src/js/09-discord-link.js`（Discord 連携）

> 最終更新: 2026-11-12

## 概要

歯車アイコンの設定タブ（`activeTab === 'status'`）。ゲームモード・エディション・プレイヤーレベル・テーマと、**トレーダーのLL/信頼度/取引額**・**ハイドアウト施設レベル**を入力する。これらは他タブ（トレーダー解放アドバイザー・ハイドアウトナビ）の判定入力になる。全データのバックアップ書き出し/復元・Discord 連携とワイプ記録もここ。

> UIアイコンは全てSVG `<Icon>`。

---

## 基本情報設定

| 項目 | state | 値 |
|---|---|---|
| ゲームモード | `gameMode` | `regular`(PvP) / `pve`(PvE) — APIの取得モードに直結。**シーズンモード（`season_N`）中はこの設定に関わらず `pvp-season` を取得**し、ラジオ下にその旨の注記を表示（フリマ価格履歴も含め、シーズン中はこの設定を使わない） |
| エディション | `edition` | ゲーム版（信頼度の初期ボーナス想定） |
| プレイヤーレベル | `playerLevel` | 数値入力 |
| 表示言語 | `uiLang` | `ja` / `en` |
| テーマ | `theme` | `THEMES` から選択（`palette` アイコン・CSS変数を `:root` に適用） |

## トレーダーステータス入力

`TRADER_LIST` の各トレーダーについて入力。

```
traderStatus[traderId] = { ll, rep, commerce }
  ll       : 現在ロイヤルティレベル
  rep      : 現在信頼度（ゲーム内表示値）
  commerce : 累計取引額
```

→ トレーダー解放アドバイザーの判定入力（[トレーダー解放機能仕様書.md](トレーダー解放機能仕様書.md)）。

## ハイドアウト施設レベル入力

```
hideoutLevels[stationId] : 現在の施設レベル
```

「＋」操作時は活動ジャーナルに `addJournalGet('{施設} Lv{n}', 'hideout')` を記録。
→ ハイドアウト収集ナビの集計入力（[ハイドアウト機能仕様書.md](ハイドアウト機能仕様書.md)）。

## データのバックアップ（書き出し / 復元）

セクション名「データのバックアップ」。localStorage の **`eft_` で始まる全キー**（全モードの `__pvp`/`__pve`/`__season_N` キー＋グローバルキー：カスタムタスク・マップピン・登録タスク品・プロモコード等）を1ファイルにまとめて入出力する。
github.io 公開版への引っ越し・PC移行・ブラウザのデータ消失対策用（2026-10-30 に旧「設定ファイル（config.json）」から置き換え）。

| UI | 関数（`03-storage.js` / `10-app-state.js`） | 動作 |
|---|---|---|
| 「バックアップを書き出し」（upload アイコン） | `exportAllData()`（async） | `eft_backup_YYYY-MM-DD.json` をダウンロード。IndexedDB の差し替えマップ画像も dataURL で同梱 |
| 「バックアップから復元」（download アイコン） | `importAllData()` → `restoreAllData(backup)` | ファイル選択 → ネイティブ `confirm`（書き出し日時・件数を表示）→ 既存の `eft_*` キーを**全削除してから**バックアップの内容を書き込み → `restoreMediaFromBackup` で差し替えマップ画像を IndexedDB に復元 → リロード |
| 保存量表示 | `getBackupSizeChars()` | `eft_*` キー＋値の文字数合計を「約X.XXMB（ブラウザ上限 約5MB）」で表示 |

**ファイル形式:**
```json
{ "type": "eft-tool-full-backup", "version": 1, "exportedAt": "2026-10-30T12:00:00.000Z",
  "data": { "eft_active_mode": "pvp", "eft_tool_v2__pvp": "{...}", "...": "..." },
  "media": { "mapOverrides": { "Customs": "data:image/png;base64,..." } } }
```
- `data` の値は localStorage の生文字列（JSON文字列のまま）。
- `media` が無い（旧）バックアップを復元した場合、IndexedDB の差し替え画像はそのまま残す。`media` がある場合は IndexedDB を全消去してから書き戻す。差し替え画像の復元だけ失敗した場合は alert（localStorage 側は復元済み）。
- 保存量表示は localStorage 分のみ（IndexedDB の画像は含まない）。
- `type` が一致しないファイルは「バックアップファイルの形式ではありません」で拒否。`eft_` 以外のキー・文字列以外の値は無視。
- **含めないキー（`BACKUP_EXCLUDE_KEYS`）**: `eft_discord_link_v1`（Discord の連携トークン）。書き出しに入れず、復元でも消さない・上書きしない（バックアップに入っていても無視）。`getBackupKeys()` で除外しているので保存量表示にも含まない。
- 書き込み途中で失敗（容量超過等）した場合は復元前のデータに戻し、alert で通知（データは元のまま）。
- **旧 config.json 形式との互換**: `type` が無く `gameMode`/`edition`/`uiLang`/`theme`/`playerLevel`/`traderStatus`/`hideoutLevels` を持つファイルは、従来どおり現在モードの設定項目だけを反映する（リロードなし）。

> 旧 `loadConfig()`（`./config.json` を fetch）・`exportConfig()`・`CONFIG_KEYS` とリポジトリ同梱の `config.json` は廃止（`loadConfig` はどこからも呼ばれていなかった）。

## ワイプ記録

新ワイプ開始時のリセット操作。ネイティブ `confirm` で確認後、以下を初期化。

```
リセット対象: スタッシュ（アイテム・通貨）/ 完了タスク / ハイドアウト進行 / トレーダーLL・信頼度・取引額
維持        : 欲しいものリスト・活動ジャーナル
※ 元に戻せない
```

## APIデータ取得（ヘッダー・全タブ共通）

ヘッダー右の「APIデータ取得 / 読込中…」ボタン（`loadAPIData`）。tarkov.dev GraphQL から
7クエリ（traders / items×2 / hideout / barters / crafts / tasks）を**並列取得**。

- **トリガー**: ページを開いた時（mount・1回）と本ボタンの手動押下のみ。**ポーリング・自動再取得は無し**。読込中はボタン `disabled`（連打防止）。
- **リトライしない**（`fetchGraphQL`）。API障害中に負荷を増やさないため。
- **エラー表示**（ヘッダーに `alert-triangle` アイコン付きで `loadError` を表示）:
  - fetch のネットワーク失敗（`TypeError`）・非JSON応答（`SyntaxError`）・`Failed to fetch`/`NetworkError`/`Load failed`/`aborted` 等
    → **「tarkov.dev サーバーが応答していません（時間をおいて「再取得」してください）」**（サーバー無応答である旨を明示）。
  - 上記以外（GraphQLのデータ起因エラー `json.errors`）→ 「APIエラー: <メッセージ>」をそのまま表示。
- **JSON API 接続中の表示**: GraphQL が使えず `json.tarkov.dev` へフォールバックした（`isFallbackActive()` → `isFallback`）とき、かつ `loadError` が無いときだけ、ヘッダーに `globe` アイコン付きの「JSON API 接続中」を薄い文字（`--text-dim`）で表示する。**警告ではなく情報表示**で、フォールバック中も全タブが通常どおり使える（2026-11-11〜。旧「一部機能制限中」表示とタブバーの半透明表示 `restricted` は廃止）。ホバーで取得元の説明（title）を出す。シーズンモードは常にこの表示になる。
- `gameMode`（PvP/PvE）・`uiLang` は取得モード/言語に直結するが、変更しても自動再取得はしない（次回の手動取得から反映）。

## 開くタブの URL ハッシュ保持（全タブ共通・2026-11-11・Issue #26）

開いているタブを **URL のハッシュ**に持たせる（例: `eft-tool.html#armor`、`https://aiuhehe.github.io/eft-companion/#armor`）。リロードやモード切替（`location.reload()`）をしても同じタブで再開できる。**localStorage には保存しない**（`eft_tool_v2`・全データバックアップは無関係）。

- **起動時**: `activeTab` の初期値は `getTabFromHash()`（`08-pre-app.js`）。ハッシュが `VALID_TAB_IDS`（`TAB_DEFS` の id ＋ `status`）に含まれればそのタブ、空・不正値（`#存在しないタブ` 等）なら設定タブ `status`。ハッシュの無い URL（普段のブックマーク等）から開くと従来どおり設定タブから始まる。
- **タブ切替時**: `activeTab` の変化を受けて `writeTabHash(id)` が `history.replaceState` でハッシュだけ置き換える（**履歴は積まない**＝何回タブを切り替えても「戻る」1回で前のページへ）。`replaceState` が例外を投げた場合は `location.replace('#id')` で代替（どちらも再読込なし）。起動時もハッシュが無ければ `#status` が付く。
- **手動でのハッシュ変更**: URL 欄でハッシュを書き換えた（`hashchange`）ときも、そのタブへ切り替わる（不正値なら設定タブ）。
- タブバーの定義は `TAB_DEFS`（`08-pre-app.js`）に一元化。`15-render-open.js` のタブバーはこれを描画するだけ。タブを追加するときは `TAB_DEFS` に足せばハッシュ復元の対象にもなる。
- 起動直後から設定タブ以外でも、`activeTab` を見る effect（アイテム一覧のウォッチボード履歴・イベント・鍵タブの価格履歴・マップ画像読込/ホイールズーム）は従来どおり動く（履歴系は `lastLoaded` 変化で API 取得後に再実行される）。

## Discord 連携（2026-11-12・Issue #32）

セクション名「Discord 連携」（`link` アイコン・「データのバックアップ」の下）。Discord 出撃共有 Bot と連携し、進行タスクの目標（共有データ v1）を送る。設計は `docs/Discord出撃共有Bot設計書.md` §11.1〜§11.3。コンポーネントは `DiscordLinkSection`（`09-discord-link.js`・App の外・自前の state）。設定タブからは `getShareData={() => buildRaidShareData({...})}` を渡すだけ。

**Bot の URL（`DISCORD_BOT_URL`）:**
- ソースには書かない。`09-discord-link.js` の `'__DISCORD_BOT_URL__'` を `build.sh` / `build.ps1` が環境変数 `DISCORD_BOT_URL` で置き換える（末尾の `/` は除く。`https://`（または `http://localhost` / `127.0.0.1`）以外・空白や `'` `"` `\` `|` `&` を含む値はビルドを止める）
- GitHub Pages 版は `pages.yml` の Build ステップでシークレット `DISCORD_BOT_URL` を渡す。PR の CI（`ci.yml`）は渡さない
- ローカルビルドは、環境変数が無ければプロジェクト直下の `.env`（gitignore 済み・`.env.example` をコピーして作る）の `DISCORD_BOT_URL=…` を読む（最後の行が有効・前後の空白と引用符は除く）
- 置き換えられていない（空でビルドした `file://` 版）ときは `DISCORD_BOT_URL === ''` となり、セクション先頭に「Bot の URL」入力欄を出す（予備）。フォーカスが外れたときに検証して `eft_discord_link_v1.botUrl` に保存。`getDiscordBotUrl(link)` は定数を優先し、無ければこの値

**未連携のとき:**
- 説明文＋連携コード入力欄（`inputMode="numeric"`・placeholder「482 913」）＋「連携する」ボタン（Enter でも可）
- `normalizeDiscordLinkCode()` で全角数字→半角・空白（全角含む）/ハイフンを除いてから `^\d{6}$` を確認。違えば送らずに「連携コードは6桁の数字です」
- `POST /api/link { code }`（`discordLinkWithCode`）→ 200 ならトークンとユーザー名を保存（同期はオフ）して「〇〇 と連携しました」
- エラー表示: `invalid_code`「コードが違うか、使用済み」/ `expired_code`「有効期限（5分）が切れています」/ 429「試行回数が多すぎます…（約N分）」（`Retry-After` ヘッダー。CORS で読めないときは本文の `retryAfter`、どちらも無ければ時間なし）/ 通信失敗「Bot に接続できませんでした」

**連携中のとき:**
- 「連携中: <ユーザー名>」＋「連携解除」ボタン → ネイティブ `confirm` → `DELETE /api/link`（Bearer）→ 結果に関わらずこのブラウザの連携情報（トークン・ユーザー名・同期・最終同期時刻）を消す。Bot に届かなかったときは「Discord で /raid unlink を実行してください」と案内
- 「Discord に同期」チェック（`syncEnabled`・**初期オフ**・連携し直すとオフに戻る）。**自動送信（変更から30秒後・§11.2）は #33 で実装予定**のため、今は設定を保存するだけ（横に「自動送信は開発中」）
- 「今すぐ送信」ボタン → `PUT /api/share`（`discordPutShare`・本文は `buildRaidShareData()` の結果）。応答の扱い（§11.2）:
  - 204 → `lastSyncAt` を更新して「送信しました」
  - 401 → 連携情報を消して（同期もオフ）「連携が解除されています。…もう一度連携してください」
  - 413 / 422 → 「アプリ（または Bot）を更新してください」
  - 429 → 「送信が多すぎます。約N秒待ってから…」
  - 通信失敗 → 「同期できませんでした（Bot に接続できません）」
- 最終同期時刻: `formatDiscordSyncTime()`（今日なら「14:32 に同期」、別の日は「11/12 14:32 に同期」）。未送信なら「まだ送信していません」
- メッセージ（成功は緑・失敗は赤）はセクション内の1行。次の操作で消える（出撃準備タブへの同期状態表示は #34）

**常に表示:** 「送る内容を確認」ボタン（`upload` アイコン）→ `downloadRaidShareData(buildRaidShareData(...))` で `eft_raidshare_YYYY-MM-DD.json` を保存（#31 で出撃準備タブに仮置きしていたものをここへ移した。連携していなくても使える）。

**保存:** グローバルキー `eft_discord_link_v1` = `{ token, userName, linkedAt, syncEnabled, lastSyncAt, botUrl? }`（モード別にしない・全データバックアップに含めない）。書き込みは `update(patch)` で、保存済みの値に差分を当ててから state に反映する（非同期処理の後でも古い state で上書きしない）。別タブでの変更は `storage` イベントで追従。
