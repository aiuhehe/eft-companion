# ステータス・設定 機能 — 機能詳細・実装仕様

> 対応ソース: `src/js/20-tab-status.js`・`src/js/09-discord-link.js`（Discord 連携）

> 最終更新: 2026-11-12

## 概要

歯車アイコンの設定タブ（`activeTab === 'status'`）。ゲームモード・エディション・プレイヤーレベル・テーマと、**トレーダーのLL/信頼度/取引額**・**ハイドアウト施設レベル**を入力する。これらは他タブ（トレーダー解放アドバイザー・ハイドアウトナビ）の判定入力になる。全データのバックアップ書き出し/復元・Discord 連携とワイプ記録もここ。

> UIアイコンは全てSVG `<Icon>`。

---

## 基本情報設定

| 項目 | state | 値 |
|---|---|---|
| ゲームモード | `gameMode` | `regular`(PvP) / `pve`(PvE) — APIの取得モードに直結。**シーズンモード（`season_current`・過去のシーズン）中はこの設定に関わらず `pvp-season` を取得**し、ラジオ下にその旨の注記を表示（フリマ価格履歴も含め、シーズン中はこの設定を使わない） |
| エディション | `edition` | ゲーム版（信頼度の初期ボーナス想定） |
| プレイヤーレベル | `playerLevel` | 数値入力 |
| 表示言語 | `uiLang` | `ja` / `en` |
| テーマ | `theme` | `THEMES` から選択（`palette` アイコン・CSS変数を `:root` に適用） |

## トレーダーステータス入力

`TRADER_LIST` の各トレーダーについて入力。

```
traderStatus[traderId] = { ll, rep, commerce }
  ll       : 現在ロイヤルティレベル
  rep      : 現在信頼度（ゲーム内表示値）
  commerce : 累計取引額
```

→ トレーダー解放アドバイザーの判定入力（[トレーダー解放機能仕様書.md](トレーダー解放機能仕様書.md)）。

「＋」操作時は活動ジャーナルに `addJournalGet('{施設} Lv{n}', 'hideout')` を記録。

## データのバックアップ（書き出し / 復元）

セクション名「データのバックアップ」。localStorage の **`eft_` で始まる全キー**（全モードの `__pvp`/`__pve`/`__season_current`/過去のシーズンのキー＋グローバルキー：カスタムタスク・マップピン・登録タスク品・プロモコード等）を1ファイルにまとめて入出力する。
github.io 公開版への引っ越し・PC移行・ブラウザのデータ消失対策用（2026-10-30 に旧「設定ファイル（config.json）」から置き換え）。

| UI | 関数（`03-storage.js` / `10-app-state.js`） | 動作 |
|---|---|---|
| 「バックアップを書き出し」（upload アイコン） | `exportAllData()`（async） | `eft_backup_YYYY-MM-DD.json` をダウンロード。IndexedDB の差し替えマップ画像も dataURL で同梱 |
| 「バックアップから復元」（download アイコン） | `importAllData()` → `restoreAllData(backup)` | ファイル選択 → ネイティブ `confirm`（書き出し日時・件数を表示）→ 既存の `eft_*` キーを**全削除してから**バックアップの内容を書き込み → `restoreMediaFromBackup` で差し替えマップ画像を IndexedDB に復元 → リロード |
| 保存量表示 | `getBackupSizeChars()` | `eft_*` キー＋値の文字数合計を「約X.XXMB（ブラウザ上限 約5MB）」で表示 |

**ファイル形式:**
```json
{ "type": "eft-tool-full-backup", "version": 1, "exportedAt": "2026-10-30T12:00:00.000Z",
  "data": { "eft_active_mode": "pvp", "eft_tool_v2__pvp": "{...}", "...": "..." },
  "media": { "mapOverrides": { "Customs": "data:image/png;base64,..." } } }
```
- `data` の値は localStorage の生文字列（JSON文字列のまま）。
- `media` が無い（旧）バックアップを復元した場合、IndexedDB の差し替え画像はそのまま残す。`media` がある場合は IndexedDB を全消去してから書き戻す。差し替え画像の復元だけ失敗した場合は alert（localStorage 側は復元済み）。
- 保存量表示は localStorage 分のみ（IndexedDB の画像は含まない）。
- `type` が一致しないファイルは「バックアップファイルの形式ではありません」で拒否。`eft_` 以外のキー・文字列以外の値は無視。
- **含めないキー（`BACKUP_EXCLUDE_KEYS`）**: `eft_discord_link_v1`（Discord の連携トークン）。書き出しに入れず、復元でも消さない・上書きしない（バックアップに入っていても無視）。`getBackupKeys()` で除外しているので保存量表示にも含まない。
- 書き込み途中で失敗（容量超過等）した場合は復元前のデータに戻し、alert で通知（データは元のまま）。
- **旧 config.json 形式との互換**: `type` が無く `gameMode`/`edition`/`uiLang`/`theme`/`playerLevel`/`traderStatus`/`hideoutLevels` を持つファイルは、従来どおり現在モードの設定項目だけを反映する（リロードなし）。

> 旧 `loadConfig()`（`./config.json` を fetch）・`exportConfig()`・`CONFIG_KEYS` とリポジトリ同梱の `config.json` は廃止（`loadConfig` はどこからも呼ばれていなかった）。

## モードバー（PvP / PvE / シーズン・全タブ共通）

タイトル下・タブバー上の `.mode-bar`（`15-render-open.js`）。`[PvP] [PvE] [Season] [過去 Season（〜YYYY/MM/DD）…] [+ 新シーズン開始]`。押すと `switchMode()` でリロードしてそのモードのデータに切り替わる。設計の詳細は CLAUDE.md「モードシステム設計」。

- **今のシーズンの id は固定の `season_current`**（2026-11-13・Issue #57）。表示は「Season」。以前の番号付き `season_N` は起動時の `migrateSeasonIds()` で `season_current` へ移す（シーズンを複数持っていた場合は番号の最も大きいもの。残りは「過去 Season N」として残る）。
- **「+ シーズン追加」**（シーズンがまだ無いとき）: `season_current` を作って切り替える。
- **「+ 新シーズン開始」**（`season_current` があるとき）: 確認ダイアログの後、今の `season_current` のデータ（`eft_*__season_current` のキー）を過去のシーズン `season_past_YYYYMMDD`（その日の日付・同じ日の2回目以降は `_2`…）へ移し、空の `season_current` に切り替える。過去のシーズンはモードバーの「Season」の右に新しい順で並び、薄い文字（`.mode-btn-past`）で出る。
- **過去のシーズンは Discord に送らない**（自動送信なし・ヘッダーの即時同期ボタンは押せず、ホバーで理由を出す）。Discord に送るのは PvP・PvE・今の Season だけ。

## APIデータの読み込み（全タブ共通）

起動時に `loadAPIData` が tarkov.dev から全データを**並列取得**する（mount 時に1回）。**手動で取得し直すボタンは無い**（2026-11-12・Issue #33 で「APIデータ取得」ボタンを廃止。起動時に読み込み、失敗しても利用者には直せないため）。読み直したいときはページをリロードする。

- **読込中の表示**: 取得中だけ、ヘッダー右に回転する `refresh` アイコン＋「読込中...」を薄い文字で出す（ボタンではない）。
- **リトライしない**（`fetchGraphQL`）。API障害中に負荷を増やさないため。
- **エラー表示**（ヘッダーに `alert-triangle` アイコン付きで `loadError` を表示）:
  - fetch のネットワーク失敗（`TypeError`）・非JSON応答（`SyntaxError`）・`Failed to fetch`/`NetworkError`/`Load failed`/`aborted` 等
    → **「tarkov.dev / json.tarkov.dev ともに応答していません（時間をおいてページをリロードしてください）」**。
  - 上記以外（GraphQLのデータ起因エラー `json.errors`）→ 「APIエラー: <メッセージ>」をそのまま表示。
- **JSON API 接続中の表示**: GraphQL が使えず `json.tarkov.dev` へフォールバックした（`isFallbackActive()` → `isFallback`）とき、かつ `loadError` が無いときだけ、ヘッダーに `globe` アイコン付きの「JSON API 接続中」を薄い文字（`--text-dim`）で表示する。**警告ではなく情報表示**で、フォールバック中も全タブが通常どおり使える（2026-11-11〜。旧「一部機能制限中」表示とタブバーの半透明表示 `restricted` は廃止）。ホバーで取得元の説明（title）を出す。シーズンモードは常にこの表示になる。**開発者向けの表示なので、手元で開いたとき（`IS_LOCAL_DEV`＝`file://` か `localhost` / `127.0.0.1`・`00-constants.js`）だけ出す**（2026-11-12。GitHub Pages 版では出さない）
- **最終取得**（`lastLoaded`・「最終取得: 2026/11/12 3:37:28」）も同じく手元で開いたときだけ出す
- `gameMode`（PvP/PvE）・`uiLang` は取得モード/言語に直結するが、変更しても自動再取得はしない。ゲームモードの補足は「※ 変更後はページをリロードしてください」。
- 旧ボタンの場所には、Discord 連携中だけ **Discord の即時同期ボタン**を出す（下の「Discord 連携」→「ヘッダーの即時同期ボタン」）。

## 開くタブの URL ハッシュ保持（全タブ共通・2026-11-11・Issue #26）

開いているタブを **URL のハッシュ**に持たせる（例: `eft-tool.html#armor`、`https://aiuhehe.github.io/eft-companion/#armor`）。リロードやモード切替（`location.reload()`）をしても同じタブで再開できる。**localStorage には保存しない**（`eft_tool_v2`・全データバックアップは無関係）。

- **起動時**: `activeTab` の初期値は `getTabFromHash()`（`08-pre-app.js`）。ハッシュが `VALID_TAB_IDS`（`TAB_DEFS` の id ＋ `status`）に含まれればそのタブ、空・不正値（`#存在しないタブ` 等）なら設定タブ `status`。ハッシュの無い URL（普段のブックマーク等）から開くと従来どおり設定タブから始まる。
- **タブ切替時**: `activeTab` の変化を受けて `writeTabHash(id)` が `history.replaceState` でハッシュだけ置き換える（**履歴は積まない**＝何回タブを切り替えても「戻る」1回で前のページへ）。`replaceState` が例外を投げた場合は `location.replace('#id')` で代替（どちらも再読込なし）。起動時もハッシュが無ければ `#status` が付く。
- **手動でのハッシュ変更**: URL 欄でハッシュを書き換えた（`hashchange`）ときも、そのタブへ切り替わる（不正値なら設定タブ）。
- タブバーの定義は `TAB_DEFS`（`08-pre-app.js`）に一元化。`15-render-open.js` のタブバーはこれを描画するだけ。タブを追加するときは `TAB_DEFS` に足せばハッシュ復元の対象にもなる。
- 起動直後から設定タブ以外でも、`activeTab` を見る effect（アイテム一覧のウォッチボード履歴・イベント・鍵タブの価格履歴・マップ画像読込/ホイールズーム）は従来どおり動く（履歴系は `lastLoaded` 変化で API 取得後に再実行される）。

## Discord 連携（2026-11-12・Issue #32）

セクション名「Discord 連携」（`link` アイコン・「データのバックアップ」の下）。Discord 出撃共有 Bot と連携し、進行タスクの目標（共有データ v1）を送る。設計は `docs/Discord出撃共有Bot設計書.md` §11.1〜§11.3。コンポーネントは `DiscordLinkSection`（`09-discord-link.js`・App の外）。連携情報・同期の状態は App で1回だけ呼ぶ `useDiscordSync()`（下の「自動同期」）が持ち、設定タブからは `discord={discordSync}` と `getShareData={() => raidShareData}` を渡す（ヘッダーの即時同期ボタンと同じ状態を見る）。

**Bot の URL（`DISCORD_BOT_URL`）:**
- ソースには書かない。`09-discord-link.js` の `'__DISCORD_BOT_URL__'` を `build.sh` / `build.ps1` が環境変数 `DISCORD_BOT_URL` で置き換える（末尾の `/` は除く。`https://`（または `http://localhost` / `127.0.0.1`）以外・空白や `'` `"` `\` `|` `&` を含む値はビルドを止める）
- GitHub Pages 版は `pages.yml` の Build ステップでシークレット `DISCORD_BOT_URL` を渡す。PR の CI（`ci.yml`）は渡さない
- ローカルビルドは、環境変数が無ければプロジェクト直下の `.env`（gitignore 済み・`.env.example` をコピーして作る）の `DISCORD_BOT_URL=…` を読む（最後の行が有効・前後の空白と引用符は除く）
- 置き換えられていない（空でビルドした `file://` 版）ときは `DISCORD_BOT_URL === ''` となり、セクション先頭に「Bot の URL」入力欄を出す（予備）。フォーカスが外れたときに検証して `eft_discord_link_v1.botUrl` に保存。`getDiscordBotUrl(link)` は定数を優先し、無ければこの値

**未連携のとき:**
- 説明文「Discord で `/raid link` を実行すると届く6桁の連携コードを入力してください。進行中タスクをお友達と連携できるようになります。」。コマンドは `DiscordCommandChip`（`.discord-cmd`・`code` 表示＋`copy` アイコンのコピーボタン。押すと1.5秒 `check` アイコン）。コピーは `copyTextToClipboard()`（クリック直後に同期で `execCommand('copy')`、だめなら `navigator.clipboard`。`file://`・埋め込みブラウザで clipboard API が拒否されるため）
- 連携コード入力欄（`.discord-code-input`・`inputMode="numeric"`・placeholder「000 000」を薄く表示）＋「連携する」ボタン（Enter でも可）
- `normalizeDiscordLinkCode()` で全角数字→半角・空白（全角含む）/ハイフンを除いて `^\d{6}$` になるまで「連携する」ボタンは押せない（`disabled`・半透明）。Enter も同じ
- `POST /api/link { code }`（`discordLinkWithCode`）→ 200 ならトークンとユーザー名を保存して連携中の表示に切り替える（成功のお知らせは出さない）
- エラー表示: `invalid_code`「コードが違うか、使用済み」/ `expired_code`「有効期限（5分）が切れています」/ 429「試行回数が多すぎます…（約N分）」（`Retry-After` ヘッダー。CORS で読めないときは本文の `retryAfter`、どちらも無ければ時間なし）/ 通信失敗「Bot に接続できませんでした」

**連携中のとき（完成後も出すもの）:**
- 「連携中: <ユーザー名>」＋「連携解除」ボタン＋「最終同期日時: 2026年11月12日 14:32」の1行だけ（最終同期日時は時計アイコンなし・`fontSize 11`・`var(--text-dim)`。ゲームモードの「※ 変更後はページをリロードしてください」と同じ見た目）。同期のメッセージ（下の「自動同期」）はこの行の最終同期日時の横に出す。最終同期日時とメッセージは `DiscordSyncStatus`（`.discord-sync-status`）で、出撃準備タブの「マップ選択」見出しの右にも同じ部品で出す（Issue #34）
- 連携解除 → ネイティブ `confirm` → `DELETE /api/link`（Bearer）→ 結果に関わらずこのブラウザの連携情報（トークン・ユーザー名・最終同期時刻・前回送った内容のハッシュ）と同期メッセージを消して未連携の表示に戻す（解除のお知らせは出さない）。Bot に届かなかったときだけエラーで「Discord で /raid unlink を実行してください」と案内
- 最終同期日時: `formatDiscordSyncTime()`（「2026年11月12日 14:32」）。未同期なら「最終同期日時: まだ同期していません」
- **同期のオン/オフ設定と「今すぐ送信」ボタンは置かない**（2026-11-12）。連携した時点で同期されていると考えるのが自然で、操作を増やさないため。すぐ送りたいときはヘッダーの即時同期ボタンで。連携中＝自動で同期する（#33）

**メッセージ:** 連携・解除・URL 入力の**エラーのときだけ**、セクション見出し「Discord 連携」の横（`.discord-link-msg`・赤＋`alert-triangle`）に出す。次の操作で消える。成功・解除のお知らせは出さない。同期のメッセージは別（下の「自動同期」）。

**自動同期（2026-11-12・Issue #33）:** `useDiscordSync(raidShareData, ready)`（`09-discord-link.js`）を App で1回だけ呼ぶ（`14-app-components.js` の末尾・`discordSync`）。`raidShareData` は `buildRaidShareData()` を `useMemo` したもの（API のタスク・カスタムタスク・進行タスク `pinnedTaskIds`・完了 `completedTaskIds`・目標チェック `raidObjChecked`・ゲームモード・言語・レベルが変わると作り直す）。`ready` は API のタスクを読み込み済みか（読む前の空の内容は送らない）。
- **連携中のときだけ**送る。共有データが変わったら、**最後の変更から30秒後**（`DISCORD_SYNC_DELAY_MS`）にまとめて `PUT /api/share`（`discordPutShare`）を1回送る。30秒の間にまた変わればそこから数え直す
- **前回送った内容と同じなら送らない**（自動も即時同期ボタンも・Issue #54）。比べるのは内容のハッシュ `raidShareHash()`（`createdAt` を除いた JSON の非暗号ハッシュ・16進32文字）。成功したときに `eft_discord_link_v1` の `lastShareHash` と `lastSentAt`（実際に送った時刻）に保存するので、リロード後も比べられる。ただし **前回の送信から6時間（`DISCORD_SHARE_FRESH_MS`）たっていたら同じ内容でも送る**（Bot は6時間で共有データを消すため。消えたまま「同じだから送らない」にならないように）
- 送る直前に `createdAt` を今の時刻に付け直す。送っている間に内容が変わっていたら、成功後にまた30秒待って送る
- 応答ごとの動き（メッセージ `syncMsg` は設定タブの最終同期日時の横とヘッダーの即時同期ボタンの左に出し、次に送信が成功したら消す）:
  - 204 → `lastSyncAt`（最終同期日時）・`lastSentAt`・`lastShareHash` を更新
  - 401 → このブラウザの連携情報を消し（未連携の表示に戻る・ヘッダーのボタンも消える）、「Discord 連携が解除されています。もう一度連携してください」
  - 413 / 422 → 連携はそのまま「アプリ（または Bot）を更新してください」。その内容（ハッシュ）は中身が変わるまで送り直さない（自動もボタンも）
  - 429 → `Retry-After` の秒数（読めなければ60秒）待って送り直す。待っている間は「送信が多すぎるため、約N秒後に送り直します」（薄い文字・`clock`）
  - 通信できない → 「同期できませんでした」（その他の HTTP エラーは「同期できませんでした（HTTP 500）」など）。次の変更か即時同期ボタンで送り直す
- 連携し直したときと連携解除のときは、`lastShareHash` などと同期メッセージを消す（新しい連携では最初に必ず送る）

**ヘッダーの即時同期ボタン（2026-11-12・Issue #33 / #54）:** `DiscordSyncButton`（`09-discord-link.js`・ヘッダー右・旧「APIデータ取得」ボタンの場所・どのタブからでも押せる）。
- **連携中だけ**出す。未連携なら何も出さない（401 で解除されたときのメッセージだけは出す）
- 押すと30秒待たずにすぐ送る。押したら必ず「同期中…」（回転する `refresh`・`disabled`）にし、同期が終わるまで押せない。前回送った内容と同じ（6時間以内）なら**送らずに**最終同期日時だけ今にするが、そのときも「同期中…」を最低0.8秒（`DISCORD_SYNC_MIN_SPIN_MS`）出す。結果はボタンが押せるように戻ることと最終同期日時の更新で分かるので、「同期済み（変更なし）」「同期しました」のような結果の文言は出さない（2026-11-12）
- **連打できない**: 送信中は `disabled`。429 で送り直しを待っている間も `disabled` で「待機中（N秒）」と残り秒数を出す。API のタスクを読み込むまでも押せない
