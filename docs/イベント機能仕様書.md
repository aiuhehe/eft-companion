# イベント機能仕様書

> 対応ソース: `src/js/29-tab-event.js`, `src/js/08-pre-app.js`, `src/js/10-app-state.js`

タブ id: `event` / ラベル: 「イベント」 / アイコン: `trophy`

期間限定イベントのタスク進行を管理するタブ。**開催中のイベントは入れ替わる**ため、この仕様書には特定のイベント名・タスク内容・セリフは書かない（それらはコード側のデータが正）。

> コード上の識別子（`BLACKOUT_TASKS_STATIC` / `eft_blackout_v1` / `isBlackoutDone` など）は最初に対応したイベント名に由来する歴史的な名前で、特定のイベント専用ではない。localStorage キー `eft_blackout_v1` はデータ保持のため改名しない（モード別の `eft_blackout_v1__{mode}` に移行済み。旧キーは PvP の引き継ぎ元として残す）。

| イベントアイテムの入手方法 | `src/js/08-pre-app.js` の `EVENT_ITEM_SOURCES` |

## データ管理方針

tarkov.dev API にイベントタスクが登録されるまでは、タスク情報を静的データで持つ。

| フェーズ | 管理方法 | 完了フラグの保存先 |
|---|---|---|
| API 未反映 | `BLACKOUT_TASKS_STATIC` にハードコード | `eft_blackout_v1__{mode}`（localStorage・モードごと） |
| API 反映済み | 同エントリの `apiId` に tarkov.dev タスク ID を設定 | `completedTaskIds`（タスク検索タブと共有） |

`apiId` が `null` の間はイベント専用フラグで完了を管理し、`apiId` を設定すると自動的に `completedTaskIds` 参照に切り替わる。
フレーバーテキスト（`lore`）は API に含まれないため、API 反映後も手動管理を続ける。

### 理想の設計（API ベース）

```
apiData.tasks（全タスク）
  ↓ タスク名で絞り込み
  ↓ taskRequirements から前提ツリーを構築
  ↓ objectives / finishRewards を API から直接取得（lang: ja で日本語化）
  ↓ completedTaskIds（タスク検索タブ共有）で完了管理
```

### API 反映確認コマンド

```powershell
$body = '{"query":"{ tasks(lang: en) { id name trader { name } } }"}'
$resp = Invoke-RestMethod -Uri "https://api.tarkov.dev/graphql" -Method Post -ContentType "application/json" -Body $body
$resp.data.tasks | Where-Object { $_.name -match "（イベントタスクの英語名）" } | Select-Object id, name
```

GraphQL 停止中は `https://json.tarkov.dev/regular/tasks` の `data.tasks` から英語名で ID を探す。

## タスクデータフィールド仕様

`BLACKOUT_TASKS_STATIC` の各エントリ:

| フィールド | 型 | 説明 |
|---|---|---|
| `key` | string | 完了フラグの識別子（`eft_blackout_v1` に保存）。**イベントをまたいで重複させない**（例: `<イベント略称>_<連番>`） |
| `apiId` | string \| null | tarkov.dev API のタスク ID。未登録なら `null` |
| `name` | string | 英語タスク名（API 登録後の照合に使用） |
| `nameJa` | string | 日本語タスク名（カード上部に大きく表示） |
| `trader` | string | 依頼トレーダー名 |
| `prereqs` | string[] | 前提タスクの `key` 配列。**すべて**完了で解放（なければ `[]`） |
| `prereqsAny` | string[] | （任意）**どれか1つ**完了で解放。分岐の後に合流するタスク用 |
| `choice` | string | （任意）排他グループ名（例: `'c1'`）。同じグループのどれかを完了すると、残りは「失敗（選択外）」表示になる |
| `branch` | `'skier'` \| `'therapist'` \| null | （任意）陣営。カード左ボーダーとフロー図ノードの色に使う（`BRANCH_COLOR`）。null は共通（アクセント色） |
| `map` | string | （任意）マップ名。ヘッダーとフロー図ノードに表示 |
| `unlockNote` | string | （任意）解放条件の補足（「○○を受注した時点で解放」など） |
| `lore` | string | 依頼内容（改行は `\n`）。セリフ全文ではなく要約で書く。API に含まれないため常に手動管理 |
| `objectives` | array | 目標リスト（`type` + 日本語 `description`）。カスタムタスク化用の追加フィールドは下記 |
| `variants` | array | （任意）前の分岐の選択で目標・報酬が変わるとき。`{ label, objectives, experience, rubles?, euros?, dollars?, rewardItems }` の配列で、指定するとカード内に2パターンを並べて表示し、`objectives`・報酬欄の代わりになる |
| `tips` | string[] | （任意）攻略メモ（アイテムの場所・必要な鍵など） |
| `pending` | boolean | （任意）名前だけ判明して詳細不明のタスク。完了ボタンを出さず「詳細未判明」と表示 |
| `experience` | number | EXP 報酬（不明なら `0`） |
| `rubles` / `euros` / `dollars` | number | 通貨報酬（₽ / € / $ のバッジ。無い通貨は省略可） |
| `rewardItems` | array | `{ id?, name, count, unlock? }` の配列。`id` は tarkov.dev のアイテムID（アイコン表示とカスタムタスクの報酬に使う）。`unlock: { trader, level }` があると「バーター解放」報酬として緑のバッジで表示 |

### objectives の追加フィールド（カスタムタスク化用・表示には使わない）

| フィールド | 説明 |
|---|---|
| `maps` | 出撃準備タブのマップ名（英語・`RAID_MAPS` と同じ）。Infected Factory → `'Factory'`、Infected Lab → `'The Lab'` |
| `count` | 個数（倒す数・納品数） |
| `target` | 倒す対象（`'Infected'` / `'Any target'` など） |
| `itemId` / `itemName` / `fir` | アイテム指定の目標 |
| `category` | 「任意の医療キット」などカテゴリ指定の目標 |
| `questItemName` | クエストアイテムの名前（入手・納品） |

### objectives の type 値（`getObjTypeLabel` 対応）

| type | アイコン | 意味 |
|---|---|---|
| `extract` | `arrow-right` | 脱出・場所を訪れる |
| `findQuestItem` | `search` | クエストアイテムを見つける |
| `findItem` | `search` | アイテムを見つける |
| `giveItem` | `package` | アイテムを納品する |
| `kill` / `shoot` | `skull` | 敵を倒す |
| `mark` / `plantItem` | `download` | マーカーを設置する / アイテムを置く |
| `visit` / `locate` | `search` | 場所を訪れる・探す |

### `EVENT_FLOW`（フロー図のレイアウト）

上から1行ずつ描画する配列。各行は次のどちらか:

| 形 | 表示 |
|---|---|
| `{ center: [key…] }` | 中央1列（共通タスク） |
| `{ skier: [key…], therapist: [key…], choice?: '見出し' }` | 左=Skier 列・右=Therapist 列。`choice` があると黄色の点線枠＋見出し＋列の間に「or」を出す分岐行になる |

行の間には下向き矢印を挟む。`BLACKOUT_TASKS_STATIC` に無い key は描画しない。

### `EVENT_PREP`

`{ name, note, itemIds?, branches? }` の配列。「先に用意しておくもの」セクションにカードで並べる。`itemIds` のアイテム画像（36px）をカード上部に並べる（「任意の医療キット」などは代表例を複数）。`branches` は必要になる陣営（`'skier'` / `'therapist'`、両方で必要なら両方）。省略は共通タスクで使うもの。カード左端の陣営バー（片方なら陣営色・両方なら上下2色・共通はアクセント）と、上部のラベル（「Skier 側」「Therapist 側」「共通」）で表す。`note` で分岐①・②のどちらの話かを明記する（陣営色は「どちらの陣営のタスクで使うか」）。

### `EVENT_ITEMS`

`{ id, name }` の配列。「イベントアイテムの使い道」セクションの対象（入手方法と相場カード・バーター表の絞り込みボタン。並び順どおりに表示）。**先頭のアイテムは金策ルートの対象**（そのアイテムを報酬とするバーター＝作り方と、そのアイテムだけで交換できる中で1個あたりの相場が最も高い品を表示）。

### `EVENT_ITEM_SOURCES` / `EVENT_BARTER_UNLOCKS`

- `EVENT_ITEM_SOURCES`: `{ [アイテムID]: [{ kind, text, tasks?, after? }] }`。入手方法カードの各行。`kind`（`barter` / `task` / `daily` / `raid` / `flea`）でアイコンが変わる（`EVENT_SOURCE_ICON`）。`text` の後ろに `tasks`（タスク key）をタスクチップで並べ、`after` を続ける。
- `EVENT_BARTER_UNLOCKS`: `{ [報酬アイテムID]: [タスク key…] }`。そのバーターを解放するタスク（どれか1つ完了で解放）。陣営ごとに別タスクで同じバーターが解放される場合は両方を並べる。記載のないバーターは解放条件を表示しない。
- どちらも情報源は Fandom Wiki（tarkov.dev の JSON API には解放タスクが入っていない＝`taskUnlock` が null）。

### アイテム画像

`itemIcon(id)` が URL を返す。優先順: `apiData.items` の `iconLink`（`unknown-item` 以外）→ `EVENT_ITEM_ICONS`（`08-pre-app.js`。tarkov.dev に画像が未登録のイベントアイテム用に Fandom Wiki のアイコン画像URLを持つ）→ `https://assets.tarkov.dev/{id}-icon.webp`（tarkov.dev の画像URL規則）。新イベントで画像の無いアイテムが出たら `EVENT_ITEM_ICONS` に足す（Wiki の `File:<アイテム名> icon.png`）。画像が無いアイテム（イベントの新アイテムなど）は読み込み失敗時に非表示。報酬バッジは20px、準備物は36px。

### カスタムタスクへの追加

タスクカード下部（分岐パターンがあるタスクは各パターン内）の「カスタムタスクに追加」ボタン。`eventTaskToCustomTask(task, variant, itemIcon)`（`08-pre-app.js`）で出撃準備タブのカスタムタスク形式に変換し、`saveCustomTasks` で保存・`pinnedTaskIds` に追加する。詳細未判明（`pending`）のタスクには出さない。

| 変換元 | 変換先 |
|---|---|
| id | `custom_event_{key}`（固定。再度押すと上書き。登録済みならボタンが「カスタムタスク登録済み（上書き）」になる） |
| 名前 | `{nameJa}（{name}）` |
| トレーダー / Wiki | `{ name: trader }` / Fandom Wiki の URL |
| 目標 | 出撃準備の編集フォームで開き直せる型に揃える: kill→`kill`、extract→`extract`、visit/locate→`locate`、plantItem→`mark`、クエストアイテム→`findItem`（FIR・仮ID）、カテゴリ→`findItem`（FIR）/`giveItem`＋`itemCategory`、アイテム→`findItem`。同じタスク内で入手するクエストアイテムの「納品」目標は重複になるので省く |
| 報酬 | `experience`、`finishRewards.items`（通貨は `CURRENCY_ITEM_IDS` のアイテムとして）、`finishRewards.offerUnlock`（`unlock` 付き報酬） |

登録後の完了管理は出撃準備・タスク検索側（`completedTaskIds`）で行い、イベントタブの完了フラグ（`eft_blackout_v1`）とは連動しない。

### エントリの雛形

```js
{
  key: '（イベント略称）_1',
  apiId: null,
  name: '（英語タスク名）',
  nameJa: '（日本語タスク名）',
  trader: '（トレーダー名）',
  prereqs: [],                    // 前提タスクの key を列挙
  lore: '（セリフ。改行は \\n で記述）',
  objectives: [
    { type: 'findQuestItem', description: '（日本語目標説明）' },
  ],
  experience: 0,
  rubles: 0,
  rewardItems: [
    { name: '（アイテム名）', count: 1 },
  ],
},
```

## 更新フロー

| 状況 | 作業 |
|---|---|
| 新しいイベントが始まった | 概要セクション JSX を書き換え、`BLACKOUT_TASKS_STATIC` を新イベントのタスクに置き換える（`key` は新しい略称で振り直す） |
| 新タスクが追加された | `BLACKOUT_TASKS_STATIC` に雛形どおり追記 |
| 目標・報酬・セリフだけ更新された | 該当エントリのフィールドのみ編集 |
| API にタスクが登録された | 反映確認コマンドで ID を取得し、該当エントリの `apiId` に設定。以降の完了操作はタスク検索タブと共有される |

## 画面構成

1. **イベント概要セクション** — イベント名・ストーリー・期間の注記。
   - **タスク欄の開閉バー**（`.event-task-toggle`）— 進行中は「イベントタスク（完了数 / 全件数 クリア済み）」、全完了時は緑系で「イベントタスクはすべて完了しています」。右のボタン「タスクツリー・詳細を閉じる／開く」で下の 2〜4 をまとめて開閉する。初期状態は **全完了なら閉じる・それ以外は開く**（`eventTasksOpen` が `null` の間は自動。ボタンを押すとセッション中はその状態を維持・保存はしない）。
2. **タスクツリーセクション** — `EVENT_FLOW` に従った分岐フロー図。ヘッダーに「完了済み / 全件数」。凡例（陣営色・状態アイコン）付き。各ノードの先頭にタスク詳細カードと同じ番号（`BLACKOUT_TASKS_STATIC` の並び順＋1。完了=緑 / 受注可能=アクセント / それ以外=グレー）。ノードをクリックすると該当タスクカードへスクロール（`#event-task-{key}`）。
3. **先に用意しておくもの** — `EVENT_PREP` をグリッドで表示（陣営バー・ラベル付き）。
4. **イベントタスク詳細セクション** — `BLACKOUT_TASKS_STATIC` 順にカード表示。**既定では「済み」のタスク（`isResolved`＝完了・分岐で失敗・分岐②で選ばなかった陣営の後続）を表示しない**ので、先頭が次にやるタスクになる。見出し右のチェックボックス「完了・選ばなかった陣営のタスクも表示（件数）」で表示すると、済みのタスクは見出し行だけに畳まれ、見出し（または左の開閉ボタン）クリックで中身を開閉する（`showSettledEventTasks` / `openSettledEventTasks`・保存しない）。非表示中はリスト末尾に「… N件を非表示中」。受注可能（`open`）なタスクはアクセント色の枠と「次にやる」バッジ。タスクツリーのノードやタスクチップで済みのタスクを選んだときは、自動でチェックをオンにしてそのカードを開いてからスクロールする。
   - この後ろに **イベントアイテムの使い道セクション**（後述）。位置は常に同じで、タスク全完了時はタスク欄（2〜4）が閉じるため「概要 → 開閉バー → 使い道」の並びになる。
5. **ボスアイテム交換セクション** — `apiData.barters` から動的取得（後述）。**該当バーターが1件以上あるときだけ表示**（データ未取得・0件のときはセクションごと非表示）。

### タスク全完了の判定（`allResolved`）

全タスクが次のどれかなら全完了とみなす: `done` / `failed` / **分岐②（`choice: 'c2'`）で選ばなかった陣営の後続タスク**（`choice` を持たず `branch` が選んだ陣営と異なるもの。前提が満たされず `locked` のまま残るため）。完了フラグはモードごと（`eft_blackout_v1__{mode}`）なので、判定もモードごと（PvP で全完了しても PvE のタスク欄は閉じない）。

### イベントアイテムの使い道セクション

`eventItemBarters`（`10-app-state.js` の useMemo）から描画する。バーター・相場はデータ取得時のモード（PvP / PvE / シーズン）のもの。

| 要素 | 内容 |
|---|---|
| 注記 | 相場 = **買うときの値段**: フリマ24h平均（無ければ24h最安）とトレーダーの最安購入価格（`buyFor` のトレーダー分・`priceRUB`）の安い方（ゲーム内のフリマにはトレーダー販売品も並ぶため）。フリマに出品できない物（Lucky Scav ジャンクボックス等）はトレーダー購入価格。どちらも無い物（武器プリセット・ビットコイン等）は「相場なし」。出品手数料は含まない・差額 = 報酬の相場 − 材料の相場 |
| 出典表示 | トレーダー購入価格を使った報酬は、報酬の相場の下に小さく「{トレーダー} LL{n} 購入価格」（`priceSources`・`.event-use-price-src`）。購入に必要な LL やタスク解放は考慮していない |
| 入手方法と相場カード | `EVENT_ITEMS` の各アイテム: 画像＋名前＋相場、**過去1週間のフリマ価格推移グラフ**、その下に `EVENT_ITEM_SOURCES` の入手方法（`.event-use-prices` / `.event-use-source`）。入手方法の `items` はアイテム画像＋「×個数」で表示（`.event-source-items`） |
| 価格推移グラフ | `MiniFleaChart`（`07-charts.js`）。平均（アクセント色）と最安（緑）の2本線・凡例・期間の最高値/最安値・始点と終点の日付・ホバーで日時と価格のツールチップ。履歴はイベントタブを開いたとき（とデータ再取得時）に `loadItemHistory` で4アイテム分を取得し（アイテム一覧タブと同じ `historyCache`・30日分）、`sliceDays(…, 7)` で7日に切り出す。出始めの極端な高値で残りが平らにならないよう、**縦軸の上限は平均価格の中央値の 2.5 倍**（超える点は上端に張り付け、最高値の横に「（上限 n で表示）」） |
| タスクチップ | タスク名を陣営色の枠で表示（完了済みは緑のチェック付き）。クリックでタスク欄を開いて（`setEventTasksOpen(true)`）そのタスクカードへスクロール（`.event-task-chip`） |
| 金策ルート | 先頭アイテム（RDA-78 ワクチン等）の作り方があるとき: 「素材の相場 → 先頭アイテムを売る（差額）」と「→ さらに {トレーダー LL} で {品} に交換（素材比の差額）」（`.event-use-route`） |
| 絞り込み | 表の上のボタン「すべて」＋ `EVENT_ITEMS` の各アイテム（画像＋名前＋件数）。選ぶとそのアイテムを材料に含むバーターだけ表示（`eventUseFilter`・保存しない）。該当0件のアイテムはボタンを出さない |

### 前提タスク判定

`29-tab-event.js` 内の `statusOf(task)` が判定する（上の「タスクの状態」表）。`prereqs` は全件完了、`prereqsAny` は1件以上完了で条件を満たす。分岐で反対側を選んだタスク（`failed`）の後続は前提が満たされないため `locked` のまま。

### ボスアイテム交換バーターの絞り込み

```js
apiData.barters.filter(b =>
  b.requiredItems.some(r => r.item.types.includes('bossItem'))
)
```

`bossItem` は tarkov.dev API がボスドロップ専用アイテムに付与するタイプ。

- **該当バーターが1件以上**: 見出し「ボスアイテム交換（件数）」＋説明「ボスドロップアイテムをトレーダーに渡すと限定アイテムと交換できます。」＋カード一覧。
- **APIデータ未取得・該当バーター0件**: セクションごと表示しない（以前の「ボス100%スポーン中」の固定文言は、開催中かどうかと無関係に出てしまうため削除）。

### ボスアイテム交換バーターカード

## localStorage キー

| キー | 内容 |
|---|---|
| `eft_blackout_v1__{mode}` | イベントタスクの完了フラグ `{ [key]: boolean }`（モードごと・全イベント共通の入れ物） |
| `eft_blackout_v1` | 旧・全モード共通の完了フラグ。PvP モードで `eft_blackout_v1__pvp` が無いときだけ読み込む（書き込みはしない・削除もしない） |

`apiId` を設定したタスクは `completedTaskIds`（`eft_tool_v2__${mode}` 内）で管理され、`eft_blackout_v1` 側の値は参照されなくなる。
