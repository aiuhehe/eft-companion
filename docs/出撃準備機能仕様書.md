# 出撃準備機能仕様書

## 概要

タブID: `raid` / アイコン: `backpack` / ラベル: 出撃準備

進行中タスク（`pinnedTaskIds`）をもとに、選択したマップで何を持ち込み・収集・設置・撃破すべきかをまとめて確認するタブ。タスク検索タブのボードと`pinnedTaskIds`を共有する（別管理ではない）。

---

## 構成セクション

### 0. カスタムタスク（APIに未登録のタスクを手動登録）

Seasonなどでタスクツリーが変わりAPIに未掲載のタスクを手動で登録できる。

- **保存先はモード非依存のグローバルキー `eft_custom_tasks_v1`（全モード共通）。** 旧モード別キーからの自動移行あり（初回のみ）。
- 登録したカスタムタスクは **自動的に `pinnedTaskIds` に追加**され、進行タスクに並ぶ（タスク検索タブのボードと共有）。
- カスタムタスクはタスク検索タブの検索結果にも含まれる（名前一致時のみ・プロジェクトタブ選択中は除外）。タスク検索タブではカスタムタスクカードにペンシルアイコンが表示され、クリックで出撃準備タブの編集フォームへ遷移。
- カード一覧はセクションヘッダーの「折りたたむ/一覧を開く」ボタンで開閉可能（`customTaskSectionOpen` state）。
- **カード表示はマップ絞り込み対応**: マップ選択中は、そのマップに関連する目標を持つタスク（マップ指定なし目標を含む）のみ表示。マップ未選択時は全件表示。
- カードヘッダー: トレーダー名バッジ + タスク名（wikiLinkがあればリンク）+ 編集(pencil)・進行追加/外し(circle-check/x)・**完了トグル(circle-check)**・削除(circle-x)ボタン。
- カード目標リスト: `label: itemText ×count [maps]` 形式で1行ずつ。カテゴリ名は日本語表示（`CATEGORY_JA` マップで変換）。
- 「＋ 追加」ボタンでフォームを開く（トグル）。「閉じる/キャンセル」クリックで編集状態もクリア。

**クイック登録**: 進行タスクの検索欄に文字を入力すると「「〇〇」をカスタムタスクとして登録」ボタンが表示される。クリックするとその文字列をタスク名として入力済みのフォームが開く（検索欄はクリア）。

**フォーム項目:**
- タスク名（必須）
- トレーダー: コンボボックス（テキスト入力 + フィルタドロップダウン）。`raidTraderNames` から絞り込み。APIデータ未取得時はハードコードリストを使用。省略可。
- Wiki URL: 手動入力（省略可）。入力するとカード表示でタスク名がリンクになる。
- 目標リスト（「+ 目標を追加」で追加）:
  - カテゴリ: 持ち込む / 収集（FIR）/ 倒す / 設置/マーク / 脱出 / 調査/特定
  - アイテム/ターゲット 検索:
    - 持ち込む・収集: 「アイテム/カテゴリ」トグルで切替。**アイテム**モード: 候補 `itemPickCandidates`（`apiData.items` ＋ **クエストアイテム**）を名前/shortNameで絞り込み（最大8件・`searchItemPickCandidates`）、選択するとIDとアイコンも保存。クエストアイテムは候補に「タスク品」と表示（`apiData.tasks` の目標の `questItem` から集めたもの。全員共通のIDがある）。**カテゴリ**モード: ハードコードされたカテゴリ名サジェスト（Household goods等13種）から絞り込み。カテゴリ目標は `item: null, itemCategory: { name }` として保存。
    - **アイテムは候補から選ぶのが必須**（2026-11-11・Issue #43）: アイテムモードで候補を選んでいない目標（`itemId` が無い）は入力欄が赤枠になり「候補から選んでください」（文字が入っていれば「候補から選び直してください」）と表示され、保存ボタンが無効になる。文字を書き換えると選択は外れる。手入力の文字はアイテムとして保存しない。
    - クエストアイテムを選んだ場合: 収集は API のタスクと同じ `type: 'findQuestItem', questItem: { id, name }`、持ち込みは `type: 'findItem', item: {…}` に `questItem: { id, name }` も付けて保存（下書きでは `isQuestItem: true`）。
    - 設置/マーク: 同じ候補（アイテム一覧＋クエストアイテム）を絞り込み。選択は任意（手入力可）。
    - 倒す: `killTargets`（APIタスクの kill/shoot objective から収集した全ターゲット名一覧）で絞り込み（最大10件）。IDなし・文字列のみ。
    - 脱出: 検索なし（テキスト入力のみ）。
    - 調査/特定: 検索なし（場所の説明を自由記述）。
  - 個数（+/-ボタン）※持ち込む・収集・倒すのみ
  - マップ選択（チップ・複数選択可。未選択 = どのマップでもOK）
- 「保存して追加」ボタン（タスク名が必須・空の場合、またはアイテム未選択の持ち込み・収集目標がある場合は無効）で保存 → 自動で `pinnedTaskIds` に追加
- **旧形式のデータ**: 以前は手入力のアイテムが仮ID `custom_item_…` で保存されていた。`openCustomTaskEdit` はこの仮IDを未選択（`itemId: null`）として読み込むので、編集フォームで赤枠になり、候補から選び直すまで保存できない（保存済みデータ自体はそのまま残る）。`findQuestItem` の目標は収集（`isQuestItem: true`）として読み込む。
- 編集モードでは「保存して更新」に変わり、同じIDのタスクを上書きする（pinnedTaskIds は変更しない）
- **編集モード時の目標IDの引き継ぎ**: `openCustomTaskEdit` でドラフトに展開する際、各目標に `origId: o.id` を保持する。`saveDraft` では `o.origId || \`custom_obj_${ts}_${i}\`` を使うことで、既存目標のIDを変えずに保存する。これにより `raidObjChecked`（目標ごとの完了チェック）が保存後もズレない。新規追加した目標のみ新しいIDを生成。APIタスク上書き（`openApiTaskEdit`）は新規タスク作成のため `origId` を保持しない（task ID 自体が変わるため checked 状態の引き継ぎ対象外）。
- **フォームに無い項目の引き継ぎ**: 編集モードで保存するとき、編集前のタスクに `finishRewards`（と `experience`）があればそのまま残す。フォームでは報酬を編集できないため、イベントタブから登録した報酬が編集で消えないようにしている。

**イベントタブからの登録**: イベントタブの各タスクカードの「カスタムタスクに追加」ボタンから、目標・報酬つきのカスタムタスクを作れる（id は `custom_event_{key}` 固定・再登録で上書き・`pinnedTaskIds` に追加）。報酬は `finishRewards`（`items` / `offerUnlock`）と `experience` に入り、タスク検索タブの「完了報酬」に表示される。変換は `08-pre-app.js` の `eventTaskToCustomTask`。詳細は `docs/イベント機能仕様書.md`。
- **編集モード時のみ**（`customTaskEditId` または `apiTaskToUnpin` が設定されている場合）、フォーム下部に**「このタスクを完了にする」ボタン**を中央寄せで表示:
  - 未完了の場合: `btn-yellow` の大きめボタン（`toggleComplete(taskId)` を呼んでフォームを閉じる）
  - 既に完了済みの場合: `btn-gray` で「完了を取り消す」に変わる（`completedTaskIds` から除去・`pinnedTaskIds` に戻す・フォームを閉じる）
- 「キャンセル」でフォームを閉じてドラフトをリセット（編集状態もクリア）

**保存されるデータ形式:**
```json
{
  "id": "custom_1720000000000",
  "name": "タスク名",
  "trader": { "name": "Prapor" },
  "objectives": [
    { "id": "custom_obj_...", "type": "findItem", "foundInRaid": true, "item": { "id": "...", "name": "GPU", "iconLink": "" }, "count": 3, "maps": [{ "name": "Customs" }] }
  ]
}
```

**state・callback:**

| 変数 | 内容 |
|---|---|
| `customTasks` | カスタムタスク配列（localStorage から復元）|
| `saveCustomTasks(tasks)` | カスタムタスクを保存してstateを更新 |
| `customTaskDraft` | フォームの下書き `{ name, traderName, objectives: [{origId, catKey, itemName, itemId, itemIconLink, isQuestItem, count, maps, useCategory, description}], wikiLink }` — `origId` は編集時のみ設定（既存目標のID引き継ぎ用）。`isQuestItem` はクエストアイテムを選んだとき `true` |
| `itemPickCandidates` / `searchItemPickCandidates(query, limit=8)` | アイテム欄の候補（`apiData.items` ＋ クエストアイテム `{ id, name, shortName, iconLink, quest }`）と絞り込み（`13-app-memos.js`）。カスタム追加フォームと OCR のその場フォームで共通 |
| `customTaskFormOpen` | フォーム表示フラグ |
| `customTaskEditId` | 編集中のカスタムタスクID（`null` = 新規追加モード）|
| `customFormTraderOpen` | トレーダードロップダウン表示フラグ |
| `customFormItemSearchIdx` | アイテム検索ドロップダウンが開いている目標インデックス（-1=閉）|
| `ocrItemPickKey` | OCR のその場フォームで候補ドロップダウンが開いているアイテム欄（`${認識行}-${目標}`・''=閉）|

### 1. マップ選択

固定マップリスト（`RAID_MAPS`・`00-constants.js`）から選択。再クリックで解除。選択状態は `raidMap` stateに保持し、localStorage（`eft_tool_v2__${mode}`）に永続化される。

```
Customs / Factory / Woods / Shoreline / Interchange /
Reserve / Lighthouse / Streets of Tarkov / The Lab / Ground Zero /
Icebreaker / The Labyrinth / Terminal
```

2026-11-11（Issue #30）に Icebreaker・The Labyrinth・Terminal を追加して13マップになった。カスタムタスクのフォームのマップボタンも同じ一覧。

**Discord 同期状態（2026-11-12・Issue #34）:** 見出し「マップ選択」の右端に、Discord 出撃共有の同期状態を小さく出す（`DiscordSyncStatus`・`09-discord-link.js`・`.discord-sync-status`）。設定タブ「Discord 連携」と同じ部品で、`link` アイコン＋「Discord 最終同期日時: 2026年11月12日 14:32」（未同期は「まだ同期していません」）と、その横に同期メッセージ（`syncMsg`・エラーは赤の `alert-triangle`、429 の待ちは `clock`）。
- **連携していないときは何も出さない**（同期のオン/オフ設定は無い＝連携中が同期中）
- 送信ボタンは置かない。送るのは変更から30秒後の自動送信と、ヘッダーの即時同期ボタン（どのタブからでも押せる）。表示は `useDiscordSync` の戻り値 `discordSync`（`14-app-components.js`）を見るだけで、送信の結果はヘッダー・設定タブと同時に変わる
- 応答ごとのメッセージは `docs/Discord出撃共有Bot設計書.md` §11.2

#### マップ名の正規化（`normalizeRaidMapName` / `normalizeRaidMaps`・`00-constants.js`）

tarkov.dev のデータでは同じマップの派生版が別マップとして登録されていて、目標によっては派生版だけが付いている。取得したデータは書き換えず、**マップでの絞り込み（`raidObjectives`・`13-app-memos.js`）で目標の `maps` を正規化してから `raidMap` と比べる**。Discord 共有データの作成（#31）でも同じ関数を使う（`docs/Discord出撃共有Bot設計書.md` §4.4）。

| tarkov.dev のマップ | 正規化後 |
|---|---|
| Night Factory・Infected Factory | Factory |
| Ground Zero 21+・Ground Zero Tutorial（ja は「Ground Zero チュートリアル」） | Ground Zero（`Ground Zero` で始まる名前すべて） |
| The Lab (Dark)・Infected Lab | The Lab |
| Labyrinth（旧マップタブのキー名） | The Labyrinth |

- 対応表は `RAID_MAP_ALIASES`。`normalizeRaidMaps(obj.maps)` は `[{ name }]` / 文字列配列のどちらも受け取り、正規化後の名前を重複なしで返す。
- これにより、派生版だけが付いた目標（例: Night Sweep の撃破目標 = Ground Zero 21+ / Customs / Night Factory / Shoreline / Woods）も Factory・Ground Zero を選んだとき表示される（2026-11-11 時点の regular で15目標が新たに表示対象）。
- API タスクをカスタムタスクとして編集するとき（`openApiTaskEdit`）・カスタムタスク編集（`openCustomTaskEdit`）も、フォームのマップボタンと一致するよう正規化してドラフトに入れる。

### 2. 進行タスク

`pinnedTaskIds` に登録された未完了タスクをチップ表示。

**開閉トグル（`raidActiveTasksOpen` / デフォルト閉・永続化なし）:** セクション見出し（シェブロン＋「進行タスク (N 件)」）をクリックでチップ一覧を開閉。**閉じていても「タスク名で検索して追加」欄・検索結果・カスタム追加ボタン/フォームは常に表示・操作可能**（隠れるのはチップ一覧のみ）。

**チップのボタン構成:**
- **鉛筆（pencil）**: カスタムタスク → `openCustomTaskEdit(id)` でフォームにロード。APIタスク → `openApiTaskEdit(task)` でAPIタスクの内容をカスタムタスクフォームに事前入力（上書き新規作成モード）。
- **×（x）**: 進行中から外す（`pinnedTaskIds` から除去のみ・削除ではない）
- **ゴミ箱（trash）**: カスタムタスクのみ表示。`customTasks`・`pinnedTaskIds`・`completedTaskIds` から同時削除。

**APIタスク上書き編集（`openApiTaskEdit`）:**
- 進行タスクチップのAPIタスクの鉛筆をクリックすると、APIタスクの名前・トレーダー・目標をカスタムタスクフォームに事前入力して開く
- フォーム枠が青（`--info`）になり「APIタスクをカスタムで上書き」と表示される
- 保存すると新しいカスタムタスクが `pinnedTaskIds` に追加され、元のAPIタスクが自動的に `pinnedTaskIds` から除外される（`apiTaskToUnpin` stateで管理）
- キャンセルした場合はAPIタスクはそのまま残る

**目標の変換ルール（`openApiTaskEdit`）:**

| APIの `o.type` | フォームの `catKey` | 値の参照先 |
|---|---|---|
| `findItem` + `foundInRaid: true` | `collect` | `o.item?.name \|\| o.itemCategory?.name \|\| o.description` |
| `findQuestItem` / `o.questItem` が存在して `o.item` がない | `collect` | `o.questItem?.name \|\| o.description` |
| `findItem` (FIRなし) / `giveItem` | `bring` | `o.item?.name \|\| o.itemCategory?.name \|\| o.description` |
| `kill` / `shoot` | `kill` | `o.target \|\| o.description` |
| `mark` / `plantItem` | `place` | `o.markerItem?.name \|\| o.item?.name`（JSON APIでplantItemがitemフィールドになる場合も対応）|
| `extract` | `extract` | `o.description` |
| `locate` / `visit` | `locate` | `o.description` |
| `buildItem` / `taskStatus` / `experience` など | `locate`（descriptionがある場合のみ）| `o.description` |
| descriptionもない未対応型 | スキップ | — |

- `findItem`/`giveItem` で `o.item?.name` が空の場合は `o.description` にフォールバックし、入力値が空にならないようにする
- `plantItem` は JSON API フォールバック時に `markerItem` でなく `item` フィールドに格納される場合があるため両方を参照
- `buildItem` 等の変換非対応型も `description` が存在すれば `locate` として可視化（Gunsmith系タスクで全目標が空になるバグを修正）

**送る内容を確認（Discord 出撃共有・2026-11-11・Issue #31）:** 見出し右の「送る内容を確認」ボタン（`upload` アイコン・カスタム追加の左）。`buildRaidShareData()` で共有データ形式 v1（形式の正本は aiuhehe/tarkov-raid-bot の `docs/設計書.md` §4・アプリでの作り方は `docs/Discord出撃共有Bot設計書.md` §4.5）を作り、`downloadRaidShareData()` で `eft_raidshare_YYYY-MM-DD.json`（整形済み）として保存する。Bot 連携が無くても使える。→ **2026-11-12（#32）で設定タブの「Discord 連携」セクションへ移し、2026-11-13（#34）で削除した**（`downloadRaidShareData` も削除）。

- 対象は進行中（`pinnedTaskIds` に登録・`completedTaskIds` に無い）のタスク。API タスクもカスタムタスクも含み、カスタムは `custom: true`。**マップ選択に関係なく全マップ分を一括**で作る。
- 目標の分類は出撃準備タブと同じ `classifyRaidObj()`（`00-constants.js`・`raidObjectives` と共通）。分類できない目標（`buildItem`・`taskStatus`・`experience` など）は含めず、目標が1件も残らないタスクは含めない。同タスク内で同アイテムが収集と持ち込みの両方にあれば持ち込みを除く（`raidObjectives` と同じ）。
- `maps[]` は `normalizeRaidMaps()` で正規化（重複なし）。マップ未指定の目標は `[]`（＝どのマップでもよい）のまま送る。出撃準備タブでもマップ未指定の目標はどのマップを選んでも表示される。
- `id` は `raidObjKey(taskId, obj)`（＝ `obj.id`、無ければ従来のキー）。`done` は `raidObjChecked` の同じキー。
- `label` は 収集/持ち込み = クエストアイテム名 → アイテム名 → カテゴリ名 → 説明文、撃破 = `target`（無ければ説明文）、設置/脱出/調査 = 説明文（無ければマーカー名）。
- 任意キーは値があるときだけ書く: `fir`（収集/持ち込みで FIR 必要）、`itemId`（アイテムの目標の `item.id`。#43 以降のカスタムタスクは候補から選んだ本物のID。#43 より前に手入力で保存された仮ID `custom_item_…` は送らない）、`categoryName`（アイテム無しのカテゴリ指定）、`questItem`（`findQuestItem`、またはカスタムタスクでクエストアイテムを持ち込む目標＝`questItem` 付きの `findItem`）、`desc`（`label` と異なるときのみ）、`detail`（撃破の部位 `(head/…)` と距離 `>=40m`。距離 0 は書かない）。
- `mode` = `activeMode`（今のシーズンは全員同じ `season_current`・過去のシーズンでは共有データを作らない・Issue #57）、`gameMode` = `loadAPIData` と同じ判定（シーズン → `pvp-season`、設定 PvE → `pve`、他 → `regular`）、`lang` = `uiLang`（`ja` / `en`）、`level` = `playerLevel`、`createdAt` = ISO 8601 UTC（ミリ秒なし）。スタッシュ・ピンなど目標以外の個人データは含めない。

**手動検索追加**: テキスト入力で `apiData.tasks`・`customTasks` を絞り込み（部分一致）。**完了済みを除く全タスク（進行中タスクも含む）が対象**。「+ 追加」でその場で `pinnedTaskIds` に追加。進行中のタスクは「進行中・編集」ボタン（緑色・鉛筆アイコン付き）を表示（「+ 追加」ボタンは非表示）。クリックすると検索欄をクリアしてタスク編集フォームを開く（カスタム→`openCustomTaskEdit`、APIタスク→`openApiTaskEdit`）。カスタムタスクにはゴミ箱ボタンも表示。

### 3. スクショからタスク登録 / 完了候補生成（OCR）

ゲーム内タスクジャーナルのスクリーンショットを読み取り、タスク名を認識して `pinnedTaskIds` に追加する機能。**複数枚対応・カスタムタスクも照合対象。**

- **ドロップゾーン**: ドラッグ＆ドロップで画像を投下。クリックしてもファイル選択ダイアログは開かない（誤操作防止）。
- **「ファイルを選択」ボタン**: ドロップゾーン下に常時表示。クリックでファイル選択ダイアログを開く。
- **`Ctrl+V` 貼り付け**: `raid`タブ表示中のみ有効（他タブではスタッシュOCRに振り分け）。クリック操作不要・グローバルに受け付ける。
- **複数ファイルを一括アップロード可能**（サムネイル表示・個別削除可）
- Tesseract.js（`eng`, PSM6）で全ファイルを順番に解析し、テキストを結合してから照合
- OCRテキストを行単位に分割 → 各行を `[...apiData.tasks, ...customTasks]` の名前と類似度比較
- スコア ≥ 0.65: 自動照合（チェック済みで表示）
- スコア 0.40〜0.64: 候補ボタンを行内に表示（選択して確定）
- 「進行タスクに追加」ボタンで `setPinnedTaskIds` に反映

**各行インライン操作（照合済み行）**
- **「編集」ボタン**（カスタムタスクのみ）→ `openCustomTaskEdit(id)` を呼び出し、進行タスクセクションのフォームを開く（目標・トレーダー・URL含む全項目が編集可能）
- **「変更」ボタン** → 検索モードに切替（別タスクを選び直せる）
- **他の候補** → 照合済み行でも他候補がある場合は表示。クリックで即差し替え。

**各行インライン操作（未照合 / 変更モード行）**
1. **候補ボタン**（score 0.40〜0.64 の上位4件）→ クリックで即確定
2. **インライン検索**（APIタスク・カスタムタスク共通）→ 選択で確定
3. **「カスタムタスクとして登録」** → インラインフォームを展開
   - タスク名（OCR認識テキストまたは検索文字列を初期値として入力済み）
   - トレーダー: `raidTraderNames` の `<select>`（省略可）
   - 目標リスト: カテゴリ（**収集FIR / 持込 / 倒す / 設置 / 脱出 / 調査/特定**）・アイテム名/ターゲット/場所名・個数・マップ選択。「+ 目標を追加」で追記可能
   - **収集・持込のアイテム欄は候補から選ぶのが必須**（2026-11-11・Issue #43）: 本体フォームと同じ候補（`searchItemPickCandidates`・アイテム一覧＋「タスク品」のクエストアイテム・アイコン付き）をドロップダウンで出す。未選択は赤枠＋「候補から選んでください」で「登録して追加」が無効。保存形式も本体フォームと同じ（アイテムID・クエストアイテムは `findQuestItem` / `questItem`）。以前の仮ID（`custom_item_…`）は作らない
   - 倒す・設置・脱出・調査は手入力のまま
   - 「登録して追加」→ カスタムタスクを新規作成・`pinnedTaskIds` に追加・行に紐づけ（タスク名が空、またはアイテム未選択の収集・持込目標があるときは無効）

**完了候補セクション**（OCR結果の下に表示）
- OCR解析完了後、`pinnedTaskIds` の中で OCR に写っていなかったタスク（APIタスク・カスタムタスク両方）を「完了候補」として列挙。タスクIDと**タスク名（大文字小文字無視）**の両方で照合し、カスタムタスクとAPIタスクで同名タスクが存在する場合も重複して表示されない
- 全件チェック済みで自動表示 → 外してから「選択したタスクを完了にする」で一括完了
- **チェックが1件も無いとき**はボタンが「なにもしない」（グレー・`x`アイコン）に切り替わる。押すと完了処理は行わず、表示だけ片付ける
- 「選択したタスクを完了にする」「なにもしない」のどちらを押しても、完了後に `resetRaidOcr()` でスクショ・認識結果・完了候補・進捗を**すべてリセット**（「クリア」ボタンと同じ状態）し、不要な表示領域を残さない
- 一括完了は `toggleComplete` と同じロジック（前提タスク連鎖・ジャーナル記録）
- **「次タスク自動追加」チェックボックス（`ocrAutoNext` / デフォルト OFF）**: ONのとき完了後に後続タスクを `pinnedTaskIds` へ自動追加。APIが古い場合は OFF 推奨。セッションごとにリセット（永続化なし）。

**ゲーム言語について**: OCRは英語文字専用のため、ゲームを英語表示にした状態でスクショを撮ることを推奨。

### 4b. 仲間の目標（参加者のボタン・Discord 出撃共有・2026-11-13・Issue #35）

同じ Discord のボードに参加している仲間の目標を、自分の目標一覧に重ねて出す。**どの参加者の目標を出すかは、参加者のボタンで1人ずつ選ぶ**（複数選べる・2026-11-14。以前の「自分の目標だけ」⇔「仲間の目標も表示」の切り替えは廃止）。ボタンの列は `FriendMemberBar`（`09-friend-board.js`）、目標一覧の位置に出す中身は `FriendBoardView`。アプリ側の決まりの正本は `docs/Discord出撃共有Bot設計書.md` §11.4、API・合算ルールの正本は Bot の設計書 §7・§8・§11.4。

**参加者のボタン（`FriendMemberBar`）**
- 枠（セクション）は付けない。マップを選んでいれば**「Customs での目標」の見出しのすぐ下**（マップ画像の上）に並べる。マップを選んでいないとき・進行タスクが無いときは見出しが無いので、目標一覧の位置の先頭に出す。
- ボタン1つ = 参加者1人（参加順）: メンバー別の色の四角（`--member-0`〜`--member-4` = 赤・青・緑・黄・紫。Discord の 🟥🟦🟩🟨🟪 と同じ割り当て）＋アバター（読めなければ出さない）＋表示名＋共有データの最終更新時刻（無ければ「未同期」）。左の線もその人の色。
- **押すとその人を目標一覧に出す／外す**（`toggleMember`）。外した人は薄く・点線・名前に取り消し線（`.is-off`）。外した人の userId は連携情報 `eft_discord_link_v1` の `hiddenMembers` に保存し、リロードしても同じ（1レイドだけ休む仲間を外して見るなど）。自分も外せる。乗せると「おびにー（自分）: 押すと目標一覧から外す」。
- 外していない参加者に**自分以外が1人でもいれば**、目標一覧を `FriendBoardView`（出している参加者だけで合算）にする。自分以外を全員外すと、ふだんの自分の目標一覧に戻る（`friendPeople.showsFriends`）。
- 右端に丸い更新ボタン（`.fb-bar-reload`）: 押すと今すぐ読み直す。乗せると「サーバー名 #チャンネル名（PvP）／最終読み込み 14:32（30秒ごとに更新）／20:32 ごろ自動終了（操作があれば延長）」。
- 参加中のボードが無いときは何も出さない（ボードを閉じた理由・一覧の読み込み失敗だけ1行で出す）。ボードを読んでいる間は「仲間の目標を読み込んでいます…」。
- **連携していないときは何も出さない**（Bot を使っていない人の画面を増やさない）。ただしボードのリンクで開いたときだけ「仲間の目標を見るには、設定タブで Discord と連携してください。」と「設定タブを開く」ボタンを出す。
- 以前の切り替えを保存していた `hideFriends` は、読み込んだときに消す。

**ボードの開き方**
- **参加中のボードを自動で開く**（ボード ID を意識させない）。出撃準備タブを開くと参加中のボード（`GET /api/boards`）を読み、あればそのボードを開く。1人が参加できるボードは1つ（Bot 側で、別のボードに参加するときは前のボードから抜けるか確認する・aiuhehe/tarkov-raid-bot#28）なので、選ぶ操作は無い。どのボードを開いているかは保存しない（リロードしても自動で開き直す）。ボードを開いていない間は一覧も30秒ごとに読み直すので、後から `/raid start` や [参加する] をしたボードも自動で開く。参加中のボードが無ければ何も出さない。
- Discord のボードの [地図で見る]（`https://aiuhehe.github.io/eft-companion/#board=<ボード ID>`）で開くと、`getTabFromHash()` が出撃準備タブを返し、`useFriendBoard` が `getBoardIdFromHash()`（`08-pre-app.js`・UUID の形だけ受け付ける）のボードを開く。開いた後、URL のハッシュは通常どおり `#raid` に書き換わる。ページを開いたままリンクを踏んだとき（`hashchange`）も同じ。
- 開いたボードを最初に読めたとき、Discord のボードでマップが選ばれていれば（`board.selectedMap`）そのマップを選ぶ。ただし自動で開いたときは、まだマップを選んでいない場合だけ（自分で選んだマップは上書きしない）。リンクで開いたときは常に選ぶ。

**読み直し・応答**
- **読み直し**: 出撃準備タブを表示していて、ブラウザのタブが表に出ている間だけ30秒ごとに `GET /api/boards/:id`（ボードを開いていなければ `GET /api/boards`）。裏から戻ったときは前回から30秒以上たっていればすぐ読む。他のタブに移ると止まる（開いているボードはそのまま。戻ればすぐ読む）。
- **応答ごと**: 401 → 連携情報を消して「Discord 連携が解除されています。設定タブでもう一度連携してください」（ヘッダーの同期と同じ扱い）／404（終了した）・403（参加していない・リンクで開いた場合）→ そのボードを閉じ、このページを開いている間は自動で開き直さない。「ボードが終了しました」／「参加していないボードです。Discord のボードで [参加する] を押すと、ここに自動で出ます」を出す（新しいボードに参加すれば、次の一覧の読み直しで自動で開く）。通信できない・その他 →「読み込めませんでした（30秒後にもう一度読みます）」と出し、前回読めた内容を出したまま次の読み直しを待つ。

**目標一覧の位置に出す中身（`FriendBoardView`）**: ボードを読めていて、自分以外の参加者を1人でも出している間は、従来の目標一覧の代わりにこちらを出す。参加者のボタンで外した人は除いて合算する。自分も参加者の1人として含まれる（外していなければ）。**自分の分は Bot に届いた共有データではなく、手元の共有データ（`raidShareData`）で合算する**（2026-11-13・チェックがすぐボードに反映される）。参加者のうち自分を探す方法（`findSelfMember`・API は自分の userId を返さない）: ① 共有データの中身（タスク ID・目標 ID・チェック）が今の自分と同じ人が1人だけ ② 連携時の名前（`eft_discord_link_v1.userName`）と同じ表示名の人が1人だけ ③ 前回見つけた人。見つからないとき・ボードのゲームモードが自分の共有データと違うときは Bot に届いた内容のまま。この差し替えは App で1回だけ行い（`useFriendBoardPeople`・`09-friend-board.js`・戻り値 `friendPeople` = `{ members（外した人を除く）, selfId, nameOf, holdersOf, taskIds, showsFriends }`）、目標一覧とマップ画像の右の一覧の両方で使う。
- **マップ未選択**: 「マップ別の目標（行き先選び）」＝ `aggregateRaidOverview()`。行は「1. Customs [色の四角…] 目標 12件（共通 3件）」で、押すとそのマップを選ぶ。並び順は Discord と同じ（固有目標がある参加者の数 → 共通の数 → 固有目標の合計数）。下に「どのマップでもOKな目標: N件（撃破 a / 収集・持ち込み b / 設置・調査・脱出 c）」。
- **マップ選択時**: 見出し「Customs での目標」＋「マップ別の一覧に戻る」ボタン、参加者のボタン、マップ画像（`MapPinVisual`・ピンが無くても地図は出す `showWhenEmpty`。ピンは自分の進行タスクの分（自分を外していなければ）＋仲間が共有しているタスクの目標のうち、出している誰かに残っている分。右の一覧の**番号の下に**、その目標が残っている人の色の四角だけを縦に並べる＝数は出さない・四角に乗せると名前。タスク名が長くても押し出されない。2026-11-14）、その下に `aggregateRaidMap()` の結果を、**自分の目標一覧と同じ6つの欄・同じ順**で出す（2026-11-13）: 「持ち込むもの」→「収集するもの（FIR）」→「設置・マーキング」→「倒すもの」→「脱出」→「調査・特定」→「どのマップでもOKな目標 (N件) — このレイドでも消化できます」（自分の目標と同じく**折りたたみ**。中も同じ6つの欄）。「共通の目標」の欄は作らない（目標の種類がまざるため）。2人以上が持つ共通の目標は、各欄の先頭（持っている人が多い順）に、左のアクセント色の線と並んだ色の四角でわかるように出す。合算（同じ目標を1行にまとめ、撃破は各自の残りを並べる）は Discord のボードと同じで、マップ指定の無い持ち込みを出さないことも同じ（Bot の §7・§8）。Discord のボードにある「共通のタスク（タスク「Debut」）」の行は**出さない**（Discord は文字数の都合で行ごとにタスク名を書けないための行で、アプリは各行の下にタスク名と誰のタスクかを出すため）。マップ別の一覧の「共通 N件」も共通の目標だけを数える `commonGoals`。
- **1行は自分の目標一覧と同じ見た目**（2026-11-13・`33-tab-raid.js` の `renderObjRow` を共用）。合算した行は `entries`（まとめる前の「誰の・どのタスクの・どの目標か」= `{ userId, colorIdx, taskId, taskName, trader, custom, objId }`）を持ち、自分の API データ（`apiData.tasks` ＋ 自分の `customTasks`）とタスク ID・目標 ID（`raidObjKey`）で突き合わせる（`fbInfo`）。タスク ID・目標 ID は API の ID なので、**仲間だけが進めているタスクも引ける**。引けた目標は自分の目標と同じに出す:
  - アイコン 28px・名前（アイテム名・カテゴリは日本語「電子部品 カテゴリ」・クエストアイテム名）・説明文の行・撃破は説明文＋「対象 ×数 (部位) 距離」・設置はマーカーのアイコンと名前・「クエストアイテム」バッジ・FIR。**名前は自分の言語**（共有した人の言語に左右されない）。
  - タスク名のリンク（押すと自分の目標と同じタスク詳細のポップアップ。仲間だけのタスクなら「進行中に追加」もできる）＋トレーダー。同じ目標を複数のタスクが持つ行は、タスクを全部並べ、2人以上の行ではタスクの前に誰のタスクかを色の四角で出す。
  - ピン: その目標に登録した自分のピンの「Customs のピンを見る」ボタン（押すとマップタブ）・メモ・必要な鍵・メモ画像。置き場所は自分の目標と同じく行の右側（下の「目標の行の作り」）。
  - チェックボックス: **自分の進行タスクの目標の行だけ**（無い行は同じ幅の空白）。チェックすると自分の `raidObjChecked` が変わり、自分の分は手元の共有データで合算するので、自分の色がすぐ消える（仲間が持っていれば行は残る。そのため行は薄くしない）。外せば戻る。同じ行に自分のタスクが複数あれば全部まとめて付け外しする。
  - 右端（自分の目標の「×数」の位置）に参加者ごとの色の四角と各自の残り「×5」を並べる。**撃破も合計しない**（残りが一番多い人の数を倒せば全員が終わる）。文字数の制限が無いので省略しない。
- 「収集するもの（FIR）」は、自分の目標と同じ「収集一覧: 1列／2列／3列／非表示」（`collectViewMode`・切替ボタンは目標の上）で出す（「非表示」なら欄ごと出さない）。1列／2列／3列の行でも共通の目標には左のアクセント色の線を付ける。
- タスク ID は共有データで目標ごとに届く（`tasks[].id`）。自分の API データで引けないのは、仲間がアプリで作った**カスタムタスク**だけ（そのタスクは仲間のアプリの中にしか無い）。その目標は簡易表示（`FriendGoalRow`）: アイテムアイコン（`apiData.items`）か種別アイコン ＋ 種別 ＋ 共有された `label` ＋ FIR ＋ 補足、下に「タスク名（カスタム）」（リンクではない）、右端に各自の残り。複数のタスクを並べる行でも、引けないカスタムタスクには「カスタム」のバッジ（`.fb-custom-badge`）を付ける。枠と余白は自分の目標の行にそろえてある。
- 誰も共有データを送っていなければ「まだ誰の目標も届いていません（参加者のアプリが同期すると表示されます）」。

**合算（`09-raid-aggregate.js`）**: Bot の `src/aggregate.ts` と同じルールの純粋な関数（`raidGoalKey` / `isRaidTargetOn` / `aggregateRaidMap` / `aggregateRaidOverview`）。コードは共有しない。2026-11-13 に Bot のテスト（`test/aggregate.test.ts`・26件）をブラウザでこの関数に対して流し、全件同じ結果になることを確かめた。Bot の合算ルールが変わったらこのファイルも合わせる。

### 5. 目標一覧（マップ選択後に表示）

選択マップ固有の目標と、マップ非依存の目標を分けて表示。目標の `maps` は正規化（§1）してから選択マップと比べる。

**目標チェックのキー（`raidObjKey(taskId, obj)`・`00-constants.js`）:** `obj.id`、無ければ `taskId + type + (item.id / questItem.id / target)`。出撃準備タブとマップタブで共通の関数（以前は両タブに同じ `getObjKey` が重複していた・2026-11-11 統合）。`eft_raid_obj_checked_v1` のキーなので**形式を変えるとチェックが消える**。

**フォールバック中の目標ID（2026-11-11・Issue #45）:** JSON API の目標は `id` と `description` に同じ翻訳キーが入っており、以前は `_applyLocale`（`01-api.js`）が `id` まで訳文に置き換えていた（言語や GraphQL 復旧の前後でキーが変わる）。現在は `id` 欄を翻訳しないので、フォールバック中も API 本来の目標ID（24桁hex）になる。
- **移行**: `loadAPIData` の後、`needsObjectiveIdMigration()` が「APIタスク（ID が24桁hex）なのに目標キーが24桁hexでない」チェック／ピンを見つけたときだけ `fetchObjectiveTextIndex(gm)`（タスクごとの「訳文（日本語・英語）→ 目標ID」）を取得し、`migrateTranslatedObjectiveIds(index)`（`03-storage.js`）で全モードの `eft_raid_obj_checked_v1__*` と `eft_task_pins_v1` の `objectiveId` を置き換える。冪等。
- 同じタスク内で訳文が重複する目標（例:「アイテム を渡す」×3）は、修正前はチェックを共有していたので**該当する目標すべてをチェック済み**にする（見た目を修正前と同じに保つ）。ピンは**並び順で最初の目標**に付け替える（複製しない）。索引に無い訳文はそのまま残す。
- 撃破対象 `targetNames` の `Any` は翻訳表ではマップ用の訳（「任意のマップ」/ Any location）なので、専用訳「任意の目標」/ Any target に置き換える（`_LOCALE_FIELD_OVERRIDES`）。

#### 5a. マップ画像ピン可視化（`MapPinVisual` コンポーネント）

目標一覧の見出し直後（収集セクション表示切替の前）に挿入される。「マップ」タブでピンを登録済みの場合にのみ表示される（登録0件なら何も表示しない）。仲間の目標（4b）を表示中は `showWhenEmpty` を付けて、ピンが無くても地図画像を出す。このときは仲間が共有しているタスクのピンも出し（出している誰かに残っている目標だけ）、右の一覧の番号の下に、その目標が残っている人の色の四角を縦に（`.map-pin-badge-col` / `.map-pin-members`・`memberMarksOf(task, obj)` = `friendPeople.holdersOf(task.id, raidObjKey(task.id, obj))`）を並べる。数は出さない。

- **コンポーネント**: `MapPinVisual`（`14-app-components.js`）
- **表示条件**: `mapImages[raidMap]` が取得済みかつ、選択マップに1件以上のピンが登録されている
- **画像**: `maps/${meta.file}` を `width:100%` で表示。`maps/` フォルダはプロジェクトルート直下
- **画像が未登録の場合**: `ensureMapImageRegistered(raidMap)` を呼び出して自動取得を試みる。取得できない間は「マップ画像が未登録です。「マップ」タブの「画像を差し替え」から…（入手先: REƎMR EFTMAPS）」と表示
- **画像の読み込み失敗（2026-10-30・Issue #1）**: メタはあるが画像が 404 等で読めない場合（バックアップ復元後の公開版など）も、`<img onError>` で検知して同じ未登録案内を表示する（壊れた画像は出さない）。差し替え画像が登録されて URL が変われば自動で地図表示に戻る
- **ピンマーカー**: 登録済みピンのうち `raidObjectives.specific`（マップ固有目標）に含まれるもののみ表示。
- **モード分離（2026-10-24）**: ピン座標（`eft_task_pins_v1`）は全モード共通だが、表示対象タスクは `raidObjectives.activeTasks`（**現モードの `pinnedTaskIds` かつ未完了**）に限定する。`allTasks` に全タスクを渡すと他モード（PvP/Season等）で登録したピンが混ざって表示されるため不可。各マーカーはカテゴリに対応したアイコン＋色（`CAT_ICON`/`CAT_COLOR`）で配置
- **吹き出し**: ピンにホバーするとタスク名・目標名の吹き出しが表示（`MapPinMarker` サブコンポーネント）。出撃準備タブ内では削除・再配置ボタンなし（閲覧専用）
- **チェック済み目標の扱い**（`isChecked(taskId, obj)` = `raidObjChecked`）: マップ上のマーカー・右側リストのバッジ・接続線をグレー（`var(--text-dim)`）にし、番号の代わりに `check` アイコンを表示。マーカーは未チェックより背面（zIndex 1）・やや半透明。並び順は **未チェック → チェック済み** の順で、各グループ内は縦位置（`pin.y`）順。番号もこの順で振られる（`sortedPins`）。チェック状態の変化は `checkedKey`（0/1 文字列）で memo 依存に反映
- **ピン座標**: 画像の実ピクセル座標で保存。表示は `left: x/width*100%`、`top: y/height*100%`

#### 目標カテゴリ

| カテゴリ | 対象 type | アイコン |
|---|---|---|
| 持ち込むもの | `findItem`（foundInRaid:false）/ `giveItem`（常にbring） | backpack |
| 収集するもの（FIR） | `findItem`（foundInRaid:true）/ `findQuestItem` | package |
| 設置・マーキング | `mark` / `plantItem` | map-pin |
| 倒すもの | `kill` / `shoot` | skull |
| 脱出 | `extract` | arrow-right |
| 調査・特定 | `locate` / `visit` | map-pin（info色）|

目標に意味を持たないタイプ（`taskStatus`, `experience`）は除外。
**`giveItem` は `foundInRaid` に関わらず常に「持ち込むもの」（bring）に分類。** EFTのAPIで giveItem は手渡しアイテムを意味し、FIR指定はあっても「収集」ではなく「持ち込み」が意図。

**カテゴリ指定アイテム（`itemCategory`）:** `findItem`/`giveItem` 系の目標で特定アイテムではなくカテゴリ（Household goods 等）を指定するもの。`obj.item` が null で `obj.itemCategory: { name }` を持つ。`CATEGORY_JA` マップで英語名を日本語に変換して表示（例: "Household goods" → "家庭用品 カテゴリ ×N"）。dedup 対象外（item.id がないため）。

**目標の行の作り（`renderObjRow`・自分の目標と仲間の目標で共通・2026-11-13）:** 左から チェックボックス → アイコン → 本文（`.obj-main`: 名前・説明文・タスク名とトレーダー）→ **ピンの情報**（`.obj-pin-side`）→ 数（自分の目標は「×N」、仲間の目標は各自の色の四角と残り）。
- ピンの情報は、その目標に登録したピンのメモ（ピンアイコン付き・同じ目標に複数あれば「[スポーン1]」）・必要な鍵（`PinItemChip`）・メモ画像（`PinImageChips`・押すと拡大）・「**Customs のピンを見る**」ボタン（ピンのあるマップごと。2個以上なら「（2個）」。押すとマップタブでそのマップを開き、そのピンの吹き出しを開く＝`setMapsHighlightedPinId`。ピンの移動・メモの編集・追加もマップタブで）。以前は本文の下に並べ、ボタンもマップ名だけだった。
- 縦に伸ばさないため、ピンの情報は本文の右の空いているところに右寄せで置く。幅が足りないとき（スマホ幅など）は折り返して本文の下に回る（`flex-wrap`。本文は幅 180px、ピンの情報は中身の幅のまま縮めず最大 260px）。
- 縦の位置をそろえる: 仲間の目標の右端の数（各自の色の四角と残り）は、ボードの人数ぶんの幅（1人あたり約 40px・4人まで）を常にとる（`fbMarkerMinWidth`）。人数の違う行が並んでもピンの情報の右端がそろい、数と重ならない。設置・マーキングのマーカー名（例「MS2000 マーカー」）は右端ではなく本文に出す（説明文に名前が入っていれば出さない）。
- ピンの無い目標には何も出さない（ピンの登録はマップタブで行う）。

**収集セクション表示切替（`collectViewMode`）:** 目標一覧の上部に表示モード切替ボタン（1列 / 2列 / 3列 / 非表示）。
- **1列（normal）**: 1行コンパクト表示。アイテム名・×N・タスク名・トレーダーを1行に収める。descriptionはカッコ内。
- **2列（2col）**: 2カラムグリッド。アイコン・アイテム名・×N のみ。
- **3列（3col）**: 3カラムグリッド。最小表示。
- **非表示（hidden）**: 収集セクションを非表示にする。

#### マップ非依存（`<details>` で折り畳み）

`objective.maps` が空配列のもの。どのマップでも消化できる目標として表示。

## データフロー

```
pinnedTaskIds（state）
  ↓ filter: !completedTaskIds.includes
[...apiData.tasks, ...customTasks] → activeTasks
  ↓ raidMap で各 objective の maps を照合
specific（このマップ固有） / anywhere（マップ非依存）
  ↓ 同タスク内で同アイテムが collect と bring の両方にある場合 bring を除去（dedup）
  ↓ cat別にグループ化
grpSpec / grpAny → 各セクションを renderSection / renderCollectSection でレンダリング
```

**重複除去（dedup）:** `findItem (FIR=true)` と `findItem (FIR=false)` が同じタスク・アイテムに存在する場合、'bring' 側を除去して 'collect' だけ表示する。キー = `taskId + '_' + itemId`。`giveItem` は常に 'bring' なので dedup 対象外。
