# プラン機能仕様書

> 対応ソース: `src/js/32-tab-wipeflow.js`

## 概要

異種混合ゴール（タスク・ハイドアウト・トレーダー解放・バーター）を1枚のキャンバスにまとめて管理する機能。
「今すぐやること」「必要アイテム合算」「ゴール詳細ツリー」を統合表示する。

- タブ id: `wipeflow`（内部 id は継続）/ ラベル「プラン」/ アイコン `calendar-plus`
- データ保存: `eft_plan_v1`（localStorage）
- 旧「序盤フロー」は完全廃止。`eft_wipeflow_v1` は不使用（データ破棄）。

---

## ゴール管理（Section A）

### ゴールの型（`planItems` 配列）

| type | 追加元 | id パターン | 追加データ |
|---|---|---|---|
| `task` | タスク検索カード | `plan_task_<taskId>` | `taskId` |
| `project_tab` | プロジェクトタブヘッダー | `plan_tab_<tabId>` | `name`, `color`, `goalTaskId` |
| `hideout` | ハイドアウトカードヘッダー | `plan_hideout_<stationId>_<level>` | `stationName`, `stationId`, `level` |
| `trader` | トレーダー解放テーブル行 | `plan_trader_<traderId>_<ll>` | `traderName`, `traderId`, `level` |
| `barter` | 欲しいものリスト（ウィッシュリスト・お気に入り） | `plan_barter_<barterKey>` | `name` |

### ゴールの達成判定（`isGoalDone`）

| type | 判定 |
|---|---|
| `task` | `completedTaskIds.includes(taskId)` |
| `project_tab` | `completedTaskIds.includes(goalTaskId)` |
| `hideout` | `hideoutLevels[stationId] >= level` |
| `trader` | `traderStatus[traderId].ll >= level` |
| `barter` | 常に false（完了状態なし） |

### UI

- ゴールチップ（`.plan-goal-chip`）: タイプ別アイコン＋ラベル＋×削除ボタン。達成済みは `.is-done`（opacity 0.5）。
- ゴールがない場合は追加方法を案内するテキストを表示。
- 「リセット」ボタン（confirm 確認）で全ゴールを削除。

## 今すぐやること（Section B）

### 着手可能タスクの定義（`planAvailableNow` useMemo）

`planTaskIds`（全ゴールの `getAncestorTaskIds` の合算）に含まれるタスクのうち、
- 未完了（`completedTaskIds` に含まれない）
- 全前提タスクが完了済み（`taskRequirements` が全て `completedTaskIds` に含まれる）

### マップタブ

- `planAvailableMaps`（useMemo）: `planAvailableNow` に含まれるタスクのマップ名一覧（重複除去・ソート）。
- タブ: `[マップ名1] [マップ名2] ... [マップ指定なし]`
  - 各マップタブ: そのマップのタスク＋**マップ指定なし**タスクを表示。
  - 「マップ指定なし」タブ: マップ指定なしタスクのみ。タスクが0件の場合は表示しない。
- 選択タブ: `planMapTab` state（null の場合は先頭タブを使用）。

### 並行/順番グループ（`groupTasks`）

| グループ | 条件 | ラベル |
|---|---|---|
| 同時進行可 | `taskSuccessorsMap[t.id]` に `planTaskIds` ∩ 未完了の後続タスクが**ない** | 「同時進行可 — 独立しているので一緒に消化できます」|
| 順番あり | 上記の後続タスクが**ある** | 「順番あり — 上から消化してください」|

#### 「次のタスクをプレビュー」トグル（`planShowNext`・既定 ON）

順番ありブロックの各タスク直下に、ロック中の次タスク（`nextLocked`）をグレーアウトで表示。
トグル OFF で非表示。

### タスク行（`PlanTaskRow`）

- ロック中行（`locked=true`）: 鍵アイコン・opacity 0.5・点線ボーダー・完了ボタンなし。
- バッジ: トレーダー名（`.plan-badge-trader`）・EXP（`.plan-badge-exp`）・どこでも（`.plan-badge-any`）・★Nゴール（`.plan-badge-multi`）。
- 「検索へ」ボタン: `setActiveTab('tasks')` + `searchForTaskByName(task.name, task.id)`。
- 「完了」ボタン: 既存 `toggleComplete(task.id)`（前提一括完了・後続ボード追加・ジャーナル記録を含む）。

## 必要アイテム合算（Section E）

### `planRequiredItems` useMemo

`planTaskIds` に含まれるタスクの `giveItem` 目的、および `planItems` の hideout/barter ゴール由来のアイテムを集計する。

各エントリ: `{ item, totalCount, firCount, sources: [{ label, count, fir }] }`

- `firCount > 0` のとき `[FIR]` バッジを表示。
- `sources` で内訳（例: 「Debut ×2 / Setup ×3[FIR]」）を表示。

### 表示条件

- 在庫（`stash[item.id]`）が `totalCount` を満たしていない行のみ表示。
- 全アイテム充足時は「必要アイテムはすべて揃っています」メッセージ。
- planRequiredItems が空（task/project_tab ゴールのみ等）の場合はセクション自体を非表示。

### 在庫操作

- 通常: `plan-pm-btn` で ±1（`updateStash(item.id, ±1)`）。
- `LARGE_INPUT_ITEM_IDS` に含まれるアイテム（通貨）: `<input type="number">` で直接入力。

## ゴール詳細ツリー（Section F）

`planItems` を1件ずつ折りたたみカード（`.plan-goal-card`）で表示。
`planOpenGoals` state で開閉を管理（各 item.id をキーとする object）。

### タイプ別の展開コンテンツ

| type | 展開内容 |
|---|---|
| `task` / `project_tab` | `PlanTree` 再帰コンポーネントで前提タスクツリーを表示。達成済みの場合は「完了済み」テキストのみ。|
| `hideout` | 「必要アイテム合算セクションに集計されています」旨のテキスト |
| `trader` | 「トレーダー解放タブで確認してください」旨のテキスト |
| `barter` | 「必要アイテム合算セクションに集計されています」旨のテキスト |

### `PlanTree` コンポーネント

- `taskId` + `seen: Set`（循環防止）を受け取る再帰コンポーネント。
- 前提タスク（`taskRequirements`）があれば上部に再帰表示し `→` 矢印でつなぐ。
- チップクリックで `setActiveTab('tasks')` + `searchForTaskByName(t.name, taskId)`。
- 完了済みチップは `.is-done`（打ち消し線・opacity）。

## state 一覧

| state | 型 | 保存先 | 説明 |
|---|---|---|---|
| `planItems` | `array` | `eft_plan_v1` | ゴール配列 |
| `planShowNext` | `boolean` | なし（揮発） | 次タスクプレビュー表示フラグ（既定 ON）|

| `planOpenGoals` | `object` | なし（揮発） | ゴール詳細カードの開閉状態 |
