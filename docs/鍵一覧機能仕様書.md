# 鍵一覧 機能 — 機能詳細・実装仕様

> 対応ソース: `src/js/31-tab-keys.js`

> 最終更新: 2026-06-29

タブ id: `keys` / ラベル: 「鍵一覧」 / アイコン: `lock` / タブ位置: 「アイテム一覧」の右隣。

## 目的

鍵（Keys）に絞ってフリマ価格推移を確認するタブ。利用可能マップ・平均価格でのソート、
マップ別セクション分け、複数の鍵のフリマ変動を1枚に重ねた折れ線グラフ（カーソルで鍵を識別）、
平均価格しきい値での絞り込みに対応する。

## 鍵の判定

`isKeyItem(item)` = `item.types` に `'keys'` を含む、または `categories` 名に `/key|鍵|キー/` を含む。
→ items クエリに **`types`** フィールドを追加済み（言語非依存の enum なので判定に使う）。

## マップ対応（重要・API制約）

tarkov.dev API は **キー→マップの構造化データを持たない**。そのため `KEY_MAP_RULES`
（`{ map, test }` の配列・`eft-tool.html` 内 module スコープ）で **英語名 `nameEn`（無ければ `name`）の
キーワードから推定**する。`keyMapsFor(item)` が一致した全マップ（複数可）を返し、未一致は `['その他']`。

- **完全ではない**（名前にマップ手掛かりが無い鍵は「その他」へ）。ルール追加・修正はこの配列で行う。
- 過去に「`room 3xx`」ルールが Customs のドアミ鍵を Shoreline に誤分類したため除去済み。
  曖昧なキーワード（部屋番号など）は誤検出を生むので入れない。

## 操作（コントロール・`status` 等と同じくlocalStorage永続化）

| state | 既定 | 役割 |
|---|---|---|
| `keyView` | `list` | 表示モード `list`（リスト）/ `overlay`（重ねグラフ）。`.key-seg` セグメントボタン |
| `keyThreshold` | `'50000'` | 平均価格しきい値。`parseShorthand` で `5万`/`100k` 等も解釈。**これ未満の鍵は非表示** |
| `keySort` | `avgDesc` | 並び替え `avgDesc`/`avgAsc`/`name` |
| `keyGroupByMap` | `true` | マップ別セクションに分けるか |

`saved.keyThreshold/keySort/keyGroupByMap/keyView` として保存（`saveState`）。

## データ構造（useMemo）

| 名前 | 内容 |
|---|---|
| `allKeys` | `apiData.items.filter(isKeyItem)`（しきい値前の全鍵） |
| `keysFiltered` | しきい値（`avg24hPrice >= 閾値`）＋ソート適用後 |
| `keysByMap` | `keysFiltered` をマップ別グループ化（1鍵が複数マップに入りうる） |
| `keyMapOrder` | マップ表示順（主要マップ順→その他を末尾） |

## 表示

- **マップ別 ON**: `keyMapOrder` ごとに折りたたみ `.section`（`chevron` で開閉・`keyOpenMaps`）。
  開いたセクション内に、`keyView` に応じてリスト or 重ねグラフ。
- **マップ別 OFF**: 単一 `.section` に全 `keysFiltered` をまとめて表示。

### リスト表示（`renderKeyList`）

`.key-row` を鍵ごとに。アイコン＋名前＋（非グループ時はマップ名）＋24h 最安/平均/最高。
行クリックで `keyOpenId` をトグルし、その鍵の **個別フリマチャート**（`<FleaHistoryChart>`・最大30日）を
`.key-chart-wrap` に展開。

### 重ねグラフ（`renderKeyOverlay` → `<MultiLineFleaChart>`）

`buildKeySeries(keys)` で各鍵を `{ id, name, shortName, color(HSL), points:[{t,price}] }` に変換し、
`historyCache[id].points` の平均価格を使う。`MultiLineFleaChart` が全系列を1枚に重ねて描画：

- 系列ごとに index ベースの HSL 色で `<polyline>`。
- **カーソル最寄りの点を全系列から探索**してハイライト（線を太く・他を淡色化）し、
  ツールチップに **鍵名・日時・平均価格** を表示（= どの鍵の線か分かる）。
- 凡例の各鍵にカーソルを乗せても同じハイライト（`onMouseEnter`）。
- まだ履歴未取得の鍵数は「（N件 読込中…）」表示。

しきい値で安い鍵を除外するとグラフが見やすくなる（1〜10万ルーブルの鍵を一掃する想定）。

## 履歴取得（負荷管理）

既存の `loadItemHistory` / `historyCache` / `historyReqRef`（重複取得防止）を再利用。
`activeTab === 'keys'` の `useEffect` で必要分のみ取得：

- リスト表示: 展開中の鍵（`keyOpenId`）のみ。
- 重ねグラフ: マップ別なら**開いているセクション**の鍵、非グループなら `keysFiltered` 全件。

## CSS（`style.css` フェーズ12）

`.key-seg` / `.key-seg-btn`（`.active`）/ `.key-row` / `.key-chart-wrap`。
線の太さ・淡色・ツールチップ枠色など状態依存値はインライン。

## 注意

- フリマ非対象の鍵（取引不可キーカード等）は履歴が空 → チャートは「履歴データがありません」。
- マップ分類は推定のため不正確な場合あり。気付いたら `KEY_MAP_RULES` を修正する。
