# 弾薬タブ 機能仕様書

> 対応ソース: `src/js/30-tab-ammo.js`

## 概要

口径ごとに弾薬を**貫通力の高い順**で一覧表示し、各弾の**入手手段**を明記するタブ（`activeTab === 'ammo'`、ラベル「弾薬」、アイコン `target`）。
タスク解禁弾・クラフト弾は**チップをクリックすると対応するタブ（タスク検索 / ハイドアウト）へ遷移**する。

- データは tarkov.dev GraphQL API の `ammo` から実データ取得（`apiData.ammo`）。localStorage 保存はしない（表示専用）。
- 弾薬は全て `noFlea`（フリマ購入不可）なので、入手手段にフリマは登場しない。

## データ取得

`QUERIES.ammo(gameMode, lang)` および `QUERIES.weapons(gameMode, lang)` を `loadAPIData` の `Promise.all` に追加。取得フィールド（ammo）:

```
ammo { caliber damage penetrationPower armorDamage fragmentationChance
  item { id name shortName iconLink types
    buyFor { price currency vendor { name ...on TraderOffer { minTraderLevel taskUnlock { id name } } } }
    craftsFor { station { id name } level }
    bartersFor { trader { id name } level taskUnlock { id name } }
  }
}
```

結果は `setApiData({ ..., ammo: ammoData.ammo || [] })` に格納。

### 武器データ取得（`QUERIES.weapons`）

`items(types: [gun])` で全武器を取得し `apiData.weapons` に格納。フィールド:

```
items(types: [gun]) { id name shortName iconLink
  properties { ...on ItemPropertiesWeapon { caliber } }
}
```

### ammo pack（弾薬パック／箱）取得

`QUERIES.ammoPacks(gameMode, lang)`（`items(type: ammoBox)`）も併せて取得し `apiData.ammoPacks` に格納。

```
items(type: ammoBox) { id name shortName iconLink
  buyFor { vendor { name normalizedName ...on TraderOffer { minTraderLevel } } }
  bartersFor { trader { name } level }
  containsItems { item { id } count }   // 中身の弾ID と 収納発数
}
```

- **重要**: 弾（バラ）は全て noFlea だが、**「弾薬パック」はフリマ取引可**。＝パックがフリマでの実質的な入手ルートになる。
- **フリマ判定は `vendor.normalizedName === 'flea-market'`** で行う（日本語モードでは `name` が「フリーマーケット」になり `name==='Flea Market'` では判定できないため）。`getAmmoAcquisitions` のフリマ除外も同じく `normalizedName` で判定。

### `ammoPackMap`（useMemo）

`apiData.ammoPacks` から `弾ID → パック配列` を構築。

- 各パックの入手元を集約: `traders`（`buyFor` のトレーダー販売＋`bartersFor` の物々交換）、`flea`（フリマ有無）。
- **同じ収納発数(`count`)のパックは1件に集約**（別ID版・入手元をマージ）。`count` 昇順にソート。
- **入手元が無いパック（`flea` も `traders` も無い＝loot専用の箱）は除外**（買えないパックは表示しない）。

### `weaponsByCaliber`（useMemo）

`apiData.weapons` から口径キー（`Caliber` プレフィックス除去後の文字列）→ 武器配列の `Map` を構築。各口径内は名前順ソート。`ammoByCaliber` の口径キーと同じ形式で管理する。

### `weaponAcqMap`（useMemo）

武器ID → `{ buy, barter, craft }` の入手情報 `Map`。`items(types: [gun])` クエリの `buyFor`/`bartersFor`/`craftsFor` は API の仕様差で正常に取得できないため、すでに取得済みの以下データから逆引きで構築する:

| ソース | 取得内容 |
|---|---|
| `apiData.items[].buyFor` | トレーダー直販・タスク解放購入（`v.trader` が存在する＝TraderOffer のみ対象。`taskUnlock { id name }` 付き） |
| `apiData.barters[].rewardItems` | 物々交換で入手できる武器とトレーダー名・LL |
| `apiData.crafts[].rewardItems` | クラフトで入手できる武器と施設名・Lv |

直販・バーターはLL昇順ソート・同一キー重複除去。

**プリセット武器の集約（重要）**: 「Mosin PU 3.5x」のような武器プリセットはベース銃（「Mosin Sniper」）とは別IDを持つ。バーターの報酬がプリセットの場合、そのままではベース銃カードで入手手段が見つからない（入手手段不明になる）。

対策として `apiData.weapons` を `types: [gun, preset]` で取得し、`properties { ... on ItemPropertiesPreset { baseItem { id } } }` でプリセット→ベース銃IDの対応表（`presetToBase`）を構築。バーター/クラフト/buyFor の逆引き時に `resolve(id)` でプリセットIDをベース銃IDに変換してから `weaponAcqMap` に集約する。これにより Mosin/VSS 等のプリセット限定バーター武器の入手手段も正しく表示される。

## 並び順（`ammoByCaliber` useMemo）

1. `caliber`（先頭の `Caliber` を除去）ごとにグルーピング。
2. 口径は**最大貫通力の高い順**に並べる（`maxPen` 降順）。
3. 各口径内の弾は**貫通力の高い順**（`penetrationPower` 降順）。

## 入手手段の分類（`getAmmoAcquisitions(item)` — モジュール関数）

`item` を受け取り、入手手段の配列を返す。各要素 `{ kind, label, taskName?, taskId?, stationId? }`。

| kind | 判定元 | 表示 | クリック挙動 |
|---|---|---|---|
| `direct` | `buyFor` のトレーダーで `taskUnlock` なし | `直販 <トレーダー> LL<n>`（最低LLの1件のみ） | なし（プレーン表示） |
| `task` | `buyFor` のトレーダーで `taskUnlock` あり | `<トレーダー> LL<n>／<タスク名>` | タスク検索タブへ遷移＋そのタスク名で検索 |
| `craft` | `craftsFor` | `クラフト <施設名> Lv<n>` | ハイドアウトタブへ遷移＋その施設だけにフィルタ |
| `barter` | `bartersFor` | `物々交換 <トレーダー> LL<n>（要:<タスク>）` | 前提タスクがあればタスク検索へ遷移（無ければ非活性） |
| `none` | 上記いずれも無い | `入手手段なし（ルート/タスク報酬のみ）` | なし |

- `Flea Market` ベンダーは除外（弾は noFlea。フリマ判定は `normalizedName === 'flea-market'`）。
- `direct`/`task`/`craft`/`none` は**バラ弾行**、`barter` は原則**パック行に集約**（下記UI節参照）。
- 手段が複数該当する弾は全てチップ表示（例: バラ弾: 直販＋クラフト／パック: ×N）。
- **`barter`（物々交換）は「トレーダーに指定アイテムを渡して交換で入手」する取引であり、フリマ（プレイヤー間オークション）とは別物**。弾は noFlea なのでそもそもフリマには出品されない。ラベルはユーザーの混同を避けるため「物々交換」と表記する（「フリマ」とは書かない）。

## 遷移ロジック

- **タスクチップ**: `setActiveTab('tasks'); searchForTaskByName(taskName, taskId)`（既存の検索欄流し込み関数を利用）。
- **クラフトチップ**: `goToHideoutStation(stationId)` を呼ぶ。
  - `setActiveTab('hideout')`。
  - `stationId` が `apiData.hideout` に存在する場合、施設フィルタ（`hideoutStationFilters`）をその施設だけ `true`・他 `false` に設定（＝その施設だけ表示）。
  - ページ先頭へスムーススクロール。
- **バーターチップ**: 前提タスク（`taskUnlock`）があるときのみタスク検索へ遷移。無い場合は `disabled`（クリック不可）。

## UI 制御

- **口径TOCサイドバー**（`AmmoCaliberContent` コンポーネント）:
  - 弾薬一覧エリア全体を `AmmoCaliberContent` でラップ。左130px幅のスティッキーサイドバー＋右コンテンツ（`flex: 1`）の横並びレイアウト。
  - サイドバーは `position: sticky; top: 4px; maxHeight: calc(100vh - 100px); overflow-y: auto` で画面内に常時表示。
  - 各ボタンをクリックすると対応する口径セクション（`id="ammo-cal-${caliber}"`）に `scrollIntoView({ behavior: 'smooth' })` でスムーズスクロール。
  - **追従（スクロールスパイ）**: `IntersectionObserver`（`rootMargin: '0px 0px -88% 0px'`）でビューポート上部に入った口径を検出し `activeCaliber` state を更新。アクティブ口径はアクセントカラーでハイライト。アクティブ項目をサイドバー内で `scrollIntoView({ block: 'nearest' })` で自動可視化。
  - 各 `AmmoCaliberSection` の root div に `id={sectionId}` と `data-caliber={caliber}` 属性を付与し、Observer のターゲットとアンカーリンクの飛び先として使用。
  - 貫通力フィルタ（`ammoMinPen`）が変わったときは `useEffect` 依存配列に含まれるため Observer が再構築され、非表示セクションを自動で除外。

- **口径並び順**（`ammoCaliberSort` state、初期 `'pen'`）: `[PEN最大順 / 口径大きい順 / 武器数多い順]` ボタンで切り替え。`sortedAmmoByCaliber` useMemo で適用。
  - `pen`: `maxPen` 降順（`ammoByCaliber` のデフォルト順）
  - `caliber`: 実口径mm降順（`caliberToMm(cal)` で変換）。`CALIBER_MM` テーブルに登録がない場合は正規表現フォールバック
  - `weapons`: その口径を使用する武器数降順（`weaponsByCaliber.get(caliber)?.length`）

- **口径→mmサイズ変換**（`caliberToMm(cal)` / `CALIBER_MM` テーブル）: `08-pre-app.js` に定義。EFTの全口径を網羅したルックアップテーブル＋フォールバックロジック。新口径追加時はテーブルに追記する。

- **口径タイトルクリックで武器パネル開閉**（`AmmoCaliberSection` コンポーネント）:
  - 口径セクションタイトルをクリックするとトグルで使用銃パネルが開閉（`useState(false)` で管理）。
  - 口径タイトル右に「N種の銃 ▲/▼」を表示。武器データが0件の口径はクリック不可。
  - 武器パネルはタイトルと弾薬リストの間に表示。`auto-fill minmax(150px, 1fr)` グリッドで横並び。
- **武器カード**（`WeaponCard` コンポーネント）:
  - 武器アイコン32px＋短縮名をカードで表示。
  - ホバーで入手方法ツールチップを表示（`position: fixed`・ビューポート端考慮）。
  - ツールチップはホバー維持可能（180ms遅延で閉じる）。
  - 表示する入手方法の種別:
    - **直販** (`buy`): `トレーダー名 LLn 直販`
    - **購入タスク解放** (`buyTask`): `トレーダー名 LLn 購入解放` ＋ タスク名ボタン（クリックでタスク検索へ）
    - **物々交換** (`barter`): `トレーダー名 LLn 物々交換`
    - **物々交換タスク解放** (`barterTask`): `トレーダー名 LLn 物々交換解放` ＋ タスク名ボタン
    - **クラフト** (`craft`): `施設名 Lvn クラフト`
    - 入手手段なし: `入手手段不明`
  - タスク名ボタンをクリックすると `setActiveTab('tasks'); searchForTaskByName(name, id)` でタスク検索へ遷移。

- **貫通力フィルタ**（`ammoMinPen` state、初期 `0`）: `[全て / 20+ / 35+ / 強い弾 47+]` ボタン。選択値以上の貫通力の弾だけ表示し、該当弾が無い口径はセクションごと非表示（`return null`）。
- **行は CSS grid**（`gridTemplateColumns: '46px 46px 34px minmax(120px,1fr) 54px minmax(0,1.7fr)'`）で6列固定。全行で同じテンプレートを使うため、アーマーダメージ列・入手チップ列が**縦に揃う**。列は順に `[PEN][ダメ][アイコン][弾名][アーマーダメージ][入手チップ群]`。
  - アイコン列は画像が無くても必ず `<span>` プレースホルダを置き、6セル構成を崩さない（グリッド崩れ防止）。
  - **PEN・ダメージ・アーマーダメージは3つとも囲み（バッジ）表示**。数値のみ表示し、`PEN`/`ダメ` 等のラベル文字は付けない（判別は色＋ツールチップ）。
    - PENバッジ = アクセント黄（`--accent` / `--accent-muted`）。
    - ダメバッジ = danger赤（`--danger-text` / `--danger-bg-mid`）。
    - アーマーダメージバッジ = 中立グレー枠（`--text-secondary` / `--bg-card` / border `--border`）。優先度が低いので彩度を落とす。
  - ツールチップ: PEN=「貫通力（アーマーを貫通できるか）」、ダメ=「ダメージ」、アーマーダメージ=「『アーマーをどれだけ破壊するか』を表します。例：アーマーダメージ59%の弾なら、2発命中でそのアーマーはほぼ耐久ゼロ（＝貫通しやすくなる／防具として機能しなくなる）。」。
  - 弾名は溢れたら省略（`ellipsis`）。
  - **入手手段は「バラ弾」「パック」の2行に分けて表示**（列6内で縦2段）。各行の先頭に幅38pxのラベル（`バラ弾` / `パック`）を置き、行間で入手チップの開始位置を揃える。「バラ弾で買えるのか・パックで買えるのか」を一目で区別できるのが目的。
    - **バラ弾行**: `getAmmoAcquisitions` のうち `direct`/`task`/`craft`/`none`（＝バラ弾の直販・タスク解禁・クラフト・入手手段なし）。`task` はタスク検索へ、`craft` はハイドアウトへ遷移（クリック可）。
    - **パック行**: `ammoPackMap[弾ID]` のパックを `[パックのアイテム画像(高さ20px)] ×<発数> <入手元>` の形で表示（発数昇順）。入手元は `フリマ / <トレーダー> LL<n> 物々交換` 等をチップ内に淡色テキストで併記。中立グレー枠・非ボタン（情報用）。ツールチップにパック正式名。
    - **バーター（物々交換）はパック側に集約**: 弾の `bartersFor` は実体がパックの取引なので、`getAmmoAcquisitions` の `barter` はバラ弾行に出さず、パックの入手元テキスト（`<トレーダー> 物々交換`）として表現する（旧仕様の「物々交換チップ」と「パックチップ」の二重表示を解消）。
    - **保険**: パックのどれにも物々交換の入手元が無いのに弾に `bartersFor` がある場合のみ、`barter` チップをパック行にフォールバック表示。
    - パック行は表示すべきパック（またはフォールバックのバーター）が1件も無ければ**非表示**。
    - 例: 4.6x30mm Action SX → バラ弾: `直販 Mechanic LL1`／パック: `×40 フリマ`（バラはMechanic直販、40発パックはフリマ限定、と明確に分かる）。
    - 例: 5.45x39mm BT gs → バラ弾: `直販 Prapor LL4`／パック: `×30 フリマ / Prapor LL2 物々交換`, `×120 フリマ`。

### 用語
- **PEN（penetrationPower / 貫通力）**: アーマーを貫通できるかを決める値。
- **アーマーダメージ（armorDamage）**: その弾が1発でアーマーの耐久値を何%削るか＝「アーマーをどれだけ破壊するか」。貫通の可否とは別に、相手の防具をどれだけ早く無力化できるかを表す（旧称「装甲」→「アーマーダメージ」に統一）。
