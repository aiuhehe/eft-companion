# ハイドアウト収集ナビ 機能 — 機能詳細・実装仕様

> 対応ソース: `src/js/22-tab-hideout.js`

> 最終更新: 2026-06-17

## 概要

ハイドアウト各施設の次レベル（または最大レベルまでの累計）アップグレードに必要なアイテムを集計し、スタッシュ在庫と突き合わせて「あと何が何個必要か」をナビゲートする。**あと1個で完成する施設**を強調表示する。

> UIアイコンは全てSVG `<Icon>`。

---

## データソース

GraphQL `hideoutStations` から取得。

```graphql
hideoutStations {
  id name
  levels {
    level
    itemRequirements { item { id name shortName iconLink } count }
  }
}
```

`STATION_NAME_OVERRIDES`（定数・[eft-tool.html:73](eft-tool.html)）で一部施設名を日本語/短縮表記に上書き。

---

## 入力ステータス

```
hideoutLevels[stationId] : 現在の施設レベル（設定タブで入力）
stash[itemId]            : スタッシュ在庫数（OCR・手入力）
```

---

## 集計ロジック（`hideoutCalc` useMemo）

```
各施設について:
  currentLv = hideoutLevels[stationId] || 0
  levelsToCalc = hideoutMode === 'next'
    ? level === currentLv + 1 のレベル
    : level > currentLv の全レベル（MAXまで累計）

  アイテムごとに needed を合算（itemMap）
  have      = stash[itemId]
  remaining = max(0, needed - have)

  items          = remaining > 0
  completedItems = remaining === 0
  alertItems     = remaining === 1            ← 「あと1個」強調対象
  pct            = Σmin(have,needed) / Σneeded  進捗率
  totalRemaining = Σremaining
```

### モード（`hideoutMode`）
- `next`: 次のレベルまで
- `max`: MAXまでの累計

### ソート非依存設計（`hideoutCalcForSort`）
ソート順がスタッシュ入力で変動しないよう、**在庫ゼロ扱い（stash非依存）の総必要数**を別 useMemo で算出し、それを並び順の基準にする。`hideoutCalc` は表示用（在庫あり）、`hideoutCalcForSort` は並び順用。

---

## 表示

### 「アップグレード準備完了！」セクション
次レベル（`currentLv + 1`）の全アイテムが在庫で充足している施設を緑系で最上部に表示（`hideoutMode` に依存せず次レベル限定で判定）。

- `hideoutCalc` に `nextLevelItems`（次レベルのアイテム×必要数）と `isReadyForUpgrade`（全充足フラグ）を追加
- 各施設行: 施設名・Lv遷移・必要アイテムチップ一覧 + **アップグレードボタン**
- ボタン押下時:
  1. `nextLevelItems` の各アイテムを `updateStash(item.id, -needed)` で減算
  2. `setHideoutLevels(p => ({ ...p, [station.id]: currentLv + 1 }))` でレベルアップ
  3. `addJournalGet(`${displayName} Lv${currentLv + 1}`, 'hideout')` でジャーナル記録

### 「あと1個で完成！」アラート
`totalRemaining === 1`（ステーション全体の残りアイテム合計が1個）の施設のみを最上部に赤系で強調（`flag` アイコン）。アイテム個別が残り1でも他に未収集アイテムがある場合は表示しない（ユーザーが「残り1個→即完成」と確信できる状態のみ対象）。

**前提ステーション条件ツリー表示（2026-08-10追加）:**
対象施設に `stationReqs` の未充足条件がある場合、メインステーションの上に前提チェーンをツリー表示する。

```
🔒 前提: 照明 Lv3 必要（現在 Lv2）
│  アイテムA 1/3  🔥アイテムB 0/1  アイテムC 2/2 ✓
↓
射撃場 Lv1 → Lv2
   🔥 ツールセット  0/1
```

- 前提施設のアイテムを `hideoutCalc`（フィルタなし）から取得して表示
- 不足アイテム: 赤チップ（残り1個は炎アイコン付き）
- 充足済みアイテム: 薄い緑チップ（opacity 0.65）
- 段階差が2以上の場合「あと N 段階」を付記
- アイテム充足済みだが未アップグレードの場合: 「設定タブでレベルを更新してください」と表示

### 施設カード一覧（`filteredHideoutCalc`）
施設ごとに必要アイテムをカード表示。各アイテムに `StashControl`（在庫の `+`/`−` または数値入力）。完了アイテムは別枠。

### 施設フィルタ（`hideoutStationFilters`）
施設名ボタンで表示対象をトグル。`{}`（空）= ALL表示。1つだけOFFにすると残り全部がONの内部表現に変換し、全ONに戻ると `{}` に正規化。

### ソート（`stationSort`）
- `default`: あと1個を優先
- `close`: 進捗率が高い順（達成に近い順・stash非依存総数基準）
- `remaining`: 残りアイテム数が少ない順

### 全施設MAX時
`hideoutCalc.length === 0` で「全施設が最大レベルです！」（`circle-check`）。

## 未実装機能メモ

### ステーション間依存条件（`stationLevelRequirements`）

アップグレードにはアイテム収集だけでなく、別ステーションの特定レベルが前提条件になる場合がある（例: 照明 Lv2→3 には発電機 Lv2 が必要）。

GraphQL スキーマ上は `stationLevelRequirements { station { id name } level }` フィールドが存在するが、**GraphQL API が現在停止中のため取得不可**（API 状況は CLAUDE.md 参照）。

**実装済み（2026-08-09）:**
- JSON API にも `stationLevelRequirements` が含まれることを確認し実装済み
- `_transformHideout`（`01-api.js`）に変換処理を追加。`station` フィールドはIDのみのためレスポンス内のステーション名マップで解決
- GraphQL クエリ（`00-constants.js`）にも追加済み（復旧時に自動反映）
- `hideoutCalc`（`13-app-memos.js`）に `stationReqs`（依存条件リスト+充足状態）・`stationReqsMet`（全充足フラグ）を追加
- 未充足条件は各ステーションカード展開時に黄系バッジで表示（「発電機 Lv2 必要（現在 Lv1）」形式）
- `isReadyForUpgrade` はアイテム充足かつ `stationReqsMet` の両方を満たした場合のみ true
