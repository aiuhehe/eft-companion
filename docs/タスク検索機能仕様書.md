# タスク検索機能 — 機能詳細・実装仕様

> 対応ソース: `src/js/24-tab-tasks.js`

> 最終更新: 2026-07-08（納品アイテム集計を+/-カウンター方式に変更、完了後解放タスクパネルを追加）

## 概要

tarkov.dev GraphQL APIから取得したタスクデータを管理・検索し、進行状況を追跡する機能。タスクの進行管理・完了記録・wiki参照をアプリ内で完結できる。
**「プロジェクトタブ」**により、特定タスクをゴールに据えてそこに至る前提タスク群だけに絞り込んだ作業ビューを作れる。

> **アイコンは全てSVG `<Icon name="..." />`。UIに絵文字は一切使わない**（例外: ネイティブ `alert`/`confirm` 内のみ）。本書中の「🔍」等は過去版の名残ではなく、対応する Icon 名を併記する。
> タスク検索の**ナビタブ・セクションタイトルのアイコンは `list-check`**（旧 `clipboard-list`）。進行タスクボードの見出しには先頭アイコンを付けない。

---

## データソース

### GraphQL クエリ
`tarkov.dev/graphql` に対して以下のフィールドを取得。

```graphql
tasks(gameMode: regular/pve, lang: ja/en) {
  id name wikiLink
  trader { id name }
  minPlayerLevel
  taskRequirements { task { id name } status }   # 前提タスク
  objectives {
    id description type
    maps { name }
    # タイプ別フィールド
    ... on TaskObjectiveItem      { item { id name shortName iconLink } count foundInRaid }
    ... on TaskObjectiveQuestItem { questItem { id name shortName } count }
    ... on TaskObjectiveShoot     { target count distance { value compareMethod } bodyParts }
    ... on TaskObjectiveMark      { markerItem { name iconLink } }
    ... on TaskObjectiveBasic     { __typename }
  }
  finishRewards {
    traderStanding { trader { name } standing }
    items { item { name iconLink } count }
    offerUnlock { trader { name } level item { name iconLink } }
  }
  experience
}
```

## プロジェクトタブ（タスク検索内のサブタブ）

タスク検索の上部に `[全タスク] [タブ…]` のサブタブが並ぶ（`.task-subtab`）。**1タブ = 1ゴールタスク**。

### データ・主要ロジック

```
taskTabs = [{ id: 'tab_'+goalTaskId, name, color, goalTaskId }]   // localStorage: eft_task_tabs_v1
activeTaskTab : 選択中タブID（'all' = 全タスク）
activeTabObj  : taskTabs.find(id === activeTaskTab) || null
tabAncestorIds: activeTabObj ? getAncestorTaskIds(goalTaskId) : null   // ゴール＋全前提を再帰収集したSet
taskTabColorMap: { taskId: 色 }  // 各タブの祖先集合を色で塗る（先頭タブ優先）
```

`getAncestorTaskIds(taskId)`：そのタスク＋ `taskRequirements` を再帰的に辿った全前提タスクのIDを含む `Set` を返す（自分自身を含む）。

### 操作

| 関数 | 動作 |
|---|---|
| `upsertTaskTab(goalTaskId, {name,color})` | そのタスクをゴールとするタブを作成/更新し、`activeTaskTab` を当該タブに切替 |
| `removeTaskTab(tabId)` | タブ削除。`activeTaskTab` を `'all'` に戻す |
| `searchForTaskByName(taskName, taskId)` | **ツリーのチップクリック先**。検索欄(`taskSearch`)にタスク名を入れて検索し、検索欄(`#task-search-input`)へスクロール。プロジェクトタブは開いたまま維持するが、クリックしたタスクが現在タブの絞り込み対象外（`tabAncestorIds` に無い）の場合だけ `'all'` に戻す（そうしないと結果0件で表示できないため） |
| `openAndScrollToTask(taskId)` | 該当カードを開いてスクロール（現在は未使用。`searchForTaskByName` に置換済み） |

### タブ作成UI
各タスクカードのヘッダー行**完了ボタンの左**にあるスキルツリーアイコン（`sitemap`・`.task-tree-btn-cell` 内）をクリック →
ポップオーバー（`.task-tag-popover`・カード基準で左寄せ・ヘッダー下に展開）で名前・色を設定して「タブを作成／更新」。

**カスタムタスク（`task.id.startsWith('custom_')`）の場合:** `.task-tree-btn-cell` にはスキルツリーボタンの代わりに `pencil` アイコンボタンを表示。クリックすると `openCustomTaskEdit(task.id)` を呼び出し、出撃準備タブの編集フォームにロードして遷移する。タブ作成機能は持たない（カスタムタスクにはタスクツリーがないため）。

### タブ選択時の挙動
- **検索結果リスト・進行タスクボードの両方**が `tabAncestorIds` に含まれるタスクだけに絞り込まれる（`filteredTasks` / `pinnedTasks` / `mapTasks`）。検索・トレーダー・マップ・種別フィルタはその部分集合に対して従来通り機能。
- タブ**最上部にスキルツリー**（`ProjectTree` 再帰コンポーネント・`.task-tab-tree`）を表示。**チップクリックで `searchForTaskByName(t.name, taskId)`** ＝そのタスク名で検索（ツリーのタスクは全て祖先集合内なのでタブは維持される）。
- **タブ削除**ボタンはツリー右上（`.task-tab-del`）。ポップオーバーには無い。
- **ゴールタスクが完了済み & 「完了タスクも表示」OFF のときは、ツリーもリストも何も表示しない**（ツリーブロックで早期 `return null`、リストは完了除外で空）。

## フィルター・検索

> UI: タスク名入力・トレーダー/マップ/種別の各 `<select>` は**同じ高さに統一**（いずれも `fontSize:14, padding:'6px 10px'` ＝実測 約35px）。フィルタ行は `align-items:flex-start` の flex で各ラベル＋入力を縦並び。

### 検索フィルター（`filteredTasks` useMemo）
タブ非選択（`'all'`）かつ検索・各フィルタが全てデフォルトのときは空配列を返す（全件は出さない設計）。**タブ選択中はデフォルトでも祖先集合を表示**する。

```
tabActive = !!tabAncestorIds
if (!tabActive && 検索空 && trader=all && map=all && type=all) return []   // 何も出さない

各タスクの除外条件:
  - showCompletedTasks=false かつ completedTaskIds に含む → 除外
  - tabActive かつ tabAncestorIds に含まれない → 除外
  - taskTraderFilter: trader.id 不一致 → 除外
  - taskMapFilter: objectives.maps[].name に無し → 除外
  - taskTypeFilter: 指定種別の objective を1つも含まない → 除外（taskMatchesType）
  - taskSearch: タスク名の部分一致（toLowerCase）
最大50件（slice(0,50)）
```

### 種別フィルタ（`taskTypeFilter` / `TASK_TYPE_FILTERS` / `taskMatchesType`）
ドロップダウン「種別」。タスクは複数 objective を持つため**「指定 type を1つ以上含む」タスク**にマッチさせる。

| value | ラベル | マッチする objective type |
|---|---|---|
| `all` | 全種類 | （絞り込みなし） |
| `kill` | キル | `kill` / `shoot` |
| `giveItem` | 納品 | `giveItem` |
| `findItem` | 回収・収集 | `findItem` / `findQuestItem` |
| `mark` | マーク設置 | `mark` |
| `plantItem` | 設置 | `plantItem` |
| `extract` | 脱出・生還 | `extract` |
| `buildItem` | 作成 | `buildItem` |

### マップ一覧（`taskMaps` useMemo）
全タスクの objectives から maps.name を収集して重複排除。マップフィルタのプルダウンに使用。

## タスク操作

### togglePin（進行タスクボード追加ボタン・`list-check`）
```
pinnedTaskIds に追加 / 除外（= 進行タスクボードへの登録/解除）
```

### toggleMapPin（ピン止めボタン・`map-pin`）
```
mapTaskIds に追加 / 除外
ピン止め時は pinnedTaskIds にも自動追加（ボードにも登録）
ピン解除時は mapTaskIds のみ除外（pinnedTaskIds は維持）
```

### ピン一括解除（「ピン止めをすべて外す」ボタン・進行タスクボードのヘッダー右）
```
表示条件: activeTaskTab === 'all' かつ pinned.length > 0
        （全タスク表示中＝プロジェクトタブでは誤操作防止のため非表示。さらにピン止め（上部固定）が
          1件以上あるときだけ表示。ピン止めが無ければ外す対象が無いのでボタン自体を出さない）
見た目: btn btn-gray btn-sm（アイコンなしのテキストボタン）。Tooltipは付けない
       （ボード枠が overflow:hidden でクリップされ読めない＆文言で自明なため）
動作: confirm() 確認 → setMapTaskIds([]) で「ピン止め（上部固定）」だけを全解除
重要: pinnedTaskIds（＝進行タスクボードの登録）には触れない。タスクはボードに進行中として残る。
      完了状態（completedTaskIds）も変更しない。
```
> このボタンが外すのは **mapTaskIds（上部固定のピン）だけ**。「ボードから外す」のは各行の
> list-check ボタン（`togglePin`）で個別に行う。ボードを空にする一括操作は用意していない。

### toggleComplete（完了ボタン・`check`）
```
完了時:
  - 対象タスク + 全前提タスク（再帰収集）を completedTaskIds に追加
  - 対象タスクを pinnedTaskIds / mapTaskIds から除外
  - 後続タスクのうち全前提が完了済みになったものを pinnedTaskIds に自動追加
  - 自動追加されたタスクIDを recentlyUnlockedTaskIds に設定（解放タスクパネル表示）
  - 活動ジャーナルの当日 tasks カウントを新規完了数ぶん加算

完了取り消し時:
  - 対象タスクのみ completedTaskIds から除外（前提タスクは維持）
  - recentlyUnlockedTaskIds をクリア
```

前提タスクの再帰収集：
```js
const collectPrereqs = (id, visited = new Set()) => {
  if (visited.has(id)) return visited;
  visited.add(id);
  task.taskRequirements.forEach(req => collectPrereqs(req.task.id, visited));
  return visited;
};
```

### TaskRow — グリッドレイアウト（`COL` / `ColHeader`）
```
列定義(11列): '28px 28px 1fr 28px 28px 28px 44px 110px 72px 130px 28px'
  map-pin(ピン) | list-check(ボード登録) | タスク名 | sitemap(ツリー/タブ作成) | link(手動登録) | calendar-plus(プラン) | check(完了) | トレーダー | EXP | 信頼度 | 開閉(chevron)
```
- **`ColHeader`（列見出し行）はグリッドに `alignItems:center`、各セルは flex で上下中央寄せ**（アイコンと「タスク名/トレーダー/EXP/信頼度」のテキストの高さが揃う。EXPは `justifyContent:flex-end` で右寄せ）。
- ツリー（タブ作成）ボタンの右に**手動登録ボタン**（`link` アイコン・後述）を配置。完了ボタンは誤クリック防止に左右余白を広げてある（`.taskrow-complete` = `padding:5px 12px`）。
- 行の背景・ボーダーは状態に応じて変化（全てCSS変数。生hex不使用）。

| 状態 | 背景 | ボーダー |
|---|---|---|
| 詳細展開中 (`open`) | `var(--bg-secondary)` | `var(--accent)` |
| タブ所属 (`memberColor`) | — | 所属タブ色（`taskTabColorMap`） |
| ピン止め済み (`isMapPinned`) | `var(--state-pin-bg-weak)` | `var(--state-pin-border)` |
| 進行中 (`isInProgress`) | `var(--state-progress-bg-weak)` | `var(--state-progress-border)` |
| ボード内 (`boardCtx`) / 通常 | `var(--bg-primary)` | `var(--border)` |
| 完了済み (`isDone`) | （上記＋）`opacity: 0.5` | — |

> 優先順位 — 背景: open > boardCtx > mapPin > inProgress > default ／ ボーダー: open > memberColor > mapPin > inProgress > default。

### 手動登録機能（2026-07-28）

APIに存在しない購入解放・クラフト解放をユーザーが手動でタスクに紐づける機能。

**ボタン**: タスクカードヘッダーの `link` アイコン（COL 5列目・ツリーボタンの右）。
- 手動登録済みのタスクは `var(--manual)` 色（紫）で強調表示。
- クリックでカードが展開し、詳細内にフォームが現れる（`manualFormTaskId === task.id` のとき表示）。

**フォーム（`ManualUnlockForm`・インラインコンポーネント）**:
- アイテム名検索（`apiData.items` から最大8件のオートサジェスト）
- 種別選択: `unlock`（購入解放 → トレーダー＋LL）/ `craft`（クラフト解放 → 施設＋レベル＋時間）
- 施設は `apiData.hideout` が読み込まれていれば select、なければ text input
- メモ欄（任意）
- 保存: `addManualUnlock(taskId, taskName, formData)` を呼び出し

**エントリ表示**: 詳細セクション内（wikiパネルより上）に紫背景のカードで一覧表示。`×` ボタンで `removeManualUnlock(id)` 削除。

**ストレージ**:
- キー: `eft_manual_unlocks_v1`（グローバル・PvP/PvE共通）
- Season モードは `eft_manual_unlocks_v1__season_N` キーが存在すれば専用データを使用し、なければ PvP/PvE データを継承（コピーオンライト: Season 内で最初に保存した時点で専用キーが作られる）
- 各エントリ構造: `{ id, taskId, taskName, type, itemId, itemName, itemIconLink, trader?, traderLevel?, station?, stationLevel?, duration?, note, addedAt }`

**逆引き連携**: `task-reward-lookup.html` の `buildIndex()` で `loadManualUnlocksForLookup()` を呼び手動エントリをマージ。ヘッダーに「手動」バッジ表示。

### TaskRow — 実装上の注意
`TaskRow` はレンダリング IIFE 内で定義されるため、`<TaskRow />` で呼ぶと毎レンダリングで全アンマウント→リマウントが発生する。

**対策**: 関数として直接呼び出す。

```js
// NG: コンポーネント呼び出し（毎回アンマウント）
{list.map(task => <TaskRow key={task.id} task={task} ... />)}

// OK: 関数呼び出し（DOMを再利用）
{list.map(task => TaskRow({ task, ... }))}
```

### 持ち物表示（常時・`.task-obj-strip` / `.obj-chip`）
`objectives` から `item && count` を持つものを抽出して常時表示。`getObjTypeLabel(type)` が返す `iconName` でアイコンを描画（`<Icon>`）。色は type で分岐。

|---|---|---|
| `giveItem` | `package` | `var(--info)` |
| `findItem` | `search` | `var(--warn-text)` |

充足（所持数 ≥ 必要数）時は `.obj-chip.is-ok`。FIR（レイド内発見）は `[FIR]` タグを付加。

## タスク詳細（展開時）

`display: none/block` 切り替えで DOM を維持（条件レンダリングでないため iframe スクロール位置が保持される）。

### 表示セクション

1. **Wikiリンク**
   - 日本語Wiki（`book` アイコン・`wikiwiki.jp/eft/{trader}/{taskName}`）
   - 翻訳Wiki（`globe` アイコン・Google翻訳経由）
   - アプリ内表示ボタン

2. **タスクツリー**（詳細内・1段）
   - 前提タスク（`taskRequirements`）をチップ表示
   - 解放されるタスク（`taskSuccessorsMap`）を表示
   - **チップクリックで `searchForTaskByName(ct.name, ct.id)`** ＝そのタスク名で検索（対象外なら `'all'` に戻して表示）。`e.stopPropagation()` でカードの開閉とは独立。
   > ゴールまでの**多段**ツリーはプロジェクトタブ最上部（`ProjectTree`）に表示。

3. **タスク内容**（オブジェクティブ）
   - `getObjTypeLabel(type)` の Icon + `translateObjective` の日本語説明
   - FIR / 個数を付記

4. **完了報酬**
   - EXP、トレーダー信頼度（`trending-up`）、アイテム、購入解放

## アプリ内Wikiパネル

### 仕組み
tarkov.dev wikiは英語のため、日本語 wikiwiki.jp から取得して表示。

```
URL構築:
  wikiLink から slug を抽出
  → https://wikiwiki.jp/eft/{traderName}/{taskName}

取得: fetchWikiHTML()
  - 複数CORSプロキシに順次フォールバック
      1. corsproxy.io
      2. api.allorigins.win
      3. api.codetabs.com
  - タイムアウト: 各8秒
  - 広告・ナビゲーション要素を DOMParser で除去
  - <base href="https://wikiwiki.jp"> を注入して相対パス解決
  - Blob URL 化して iframe に渡す
```

### 状態管理（wikiPanels マップ）
```ts
wikiPanels: {
  [jpWikiUrl: string]: {
    open: boolean
    loading: boolean
    blobUrl: string | null
    error: string | null
    title: string | null
  }
}
```

各タスクのパネルが独立して管理されるため、複数タスクのパネルを同時に開いた状態を維持できる。

### キャッシュ戦略
```
wikiBlobCache (useRef): { [url]: blobUrl }
  - state と独立して保持（再マウント後も即復元）
  - 同じURLの再表示時は fetch しない
  - 検索フィールド変更時に wikiPanels をリセット（キャッシュは維持）
```

### iframe スクロール保持
`{open && <iframe />}` ではなく `display: none/block` を使用することで、タスク詳細の開閉時に iframe がアンマウントされずスクロール位置が保持される。

## サマリー（SummaryBadges）

進行タスクボードのヘッダーに合計を表示。

```js
const calcTotals = (tasks) => tasks.reduce((acc, task) => {
  acc.exp += task.experience || 0;
  task.finishRewards?.traderStanding?.forEach(ts => {
    acc.rep[ts.trader.name] = (acc.rep[ts.trader.name] || 0) + ts.standing;
  });
  return acc;
}, { exp: 0, rep: {} });
```

- 合計EXP: **テキストのみ**（枠・背景なし。色 `var(--warn-text)`。タスクカードの `.task-exp` と同じ装飾方針）
- トレーダー信頼度合計: テキストのみ（枠なし・`var(--state-ok-text)`）

## タスク説明の日本語化（translateObjective）

APIから返される英語の説明文を正規表現パターンマッチで日本語化。

主なパターン例：

| 英語パターン | 日本語出力 |
|---|---|
| `Find N X in raid` | `レイド内で「X」をN個見つける` |
| `Hand over N X to Trader` | `TraderにXをN個渡す` |
| `Kill N X` | `Xをn体倒す` |
| `Survive and extract from Map` | `Mapから生き残って脱出する` |
| `Locate X on Map` | `MapでXの場所を特定する` |
| `Reach level N` | `プレイヤーレベルNに到達する` |

パターン未一致の場合は原文をそのまま表示。
