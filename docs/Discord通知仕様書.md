# Discord 通知 仕様書

PR の動きを Discord の**フォーラムチャンネル**に通知する GitHub Actions。

- ワークフロー: `.github/workflows/discord-notify.yml`
- 処理本体: `.github/scripts/discord_notify.py`（Python 標準ライブラリのみ・Discord Bot の REST API を直接呼ぶ）
- PR のコードは checkout も実行もしない。スクリプトは常に `main` から取り出す（シークレットを扱うため）。

## 基本の形

- **1 PR = フォーラムの 1 投稿（スレッド）**。PR が作られたら投稿を作り、以降の出来事はその投稿に返信する。
- スレッド ID は、PR に付ける `github-actions[bot]` のコメント（「Discord スレッド: <リンク>」＋ `<!-- discord-thread:ID -->`）に保存する。PR から Discord へ飛ぶリンクも兼ねる。
- この仕組みを入れる前からある PR にはスレッドが無い。開いている PR は、コメントやラベルなどの出来事があった時点で作られる（手動で作る方法は後述）。

## 色の意味（状態だけを表す）

PR の出どころ（スケジュールタスクかどうか・誰が作ったか）では色を変えない。

| 色 | 意味 | 使う場面 |
|---|---|---|
| 青 | 進行中 | 開いている PR の最初の投稿、再オープン・ドラフト解除の返信 |
| オレンジ | 相談が必要 | `needs-discussion` が付いている間の最初の投稿、ラベルが付いたときの返信 |
| 赤 | 問題あり | 修正依頼、CI 失敗、放置 PR があるときのまとめ |
| 緑 | 良い・完了 | 承認、マージ済みの最初の投稿、サイトに公開 |
| 灰 | 中立・終了 | コメント、クローズ（マージなし）の最初の投稿、放置のないまとめ |

**最初の投稿の色は PR の状態に合わせて塗り替える**（`sync_state`：ラベル変更・マージ・クローズ・再オープン・タイトル変更のたび。編集なので通知は鳴らない）。

## スケジュールタスクの PR

ラベル `event` が付いている、またはブランチが `event/` で始まる PR は、毎日のイベント更新チェック（スケジュールタスク）が作ったものとして扱う。

- フォーラムのタグ `スケジュール` を付ける
- 投稿の文言を「新しい PR（スケジュールタスク）」にする・まとめにも「スケジュールタスク」と表示

それ以外の PR（セッションで作ったもの・手で作ったもの・外部の人のもの）は区別しない。

## 出来事ごとの動き

| 出来事 | 動き |
|---|---|
| PR の作成 | フォーラムに投稿を作る（変更行数・触った場所（タブ名）・Issue へのリンク・ブランチ・本文の冒頭）。`needs-discussion` ラベル付きならメンション |
| 再オープン | 「再オープンされました」と返信し、色・タグ・リアクションを戻す |
| ドラフト解除 | 「ドラフトが解除され、レビュー待ちになりました」と返信 |
| マージ / クローズ | **返信はしない**。最初の投稿を緑（マージ）/ 灰（クローズ）に塗り替え、✅ / ❌ のリアクションとタグ `マージ済み` / `クローズ` を付ける |
| `needs-discussion` ラベルが付いた | 最初の投稿をオレンジにし、Discord のタグ `要検討` を付け、メンション付きで返信 |
| ラベルが外れた | 色とタグを付け直す |
| タイトル変更 | 投稿とスレッドのタイトルを変える |
| コメント | 返信（ボットのコメントは流さない） |
| レビュー | 承認（緑）/ 修正依頼（赤）/ コメント（灰）として返信。行コメントだけのレビューは最初の 5 件を並べる。ボットは流さない |
| ビルドチェック（`ci.yml`）失敗 | 赤で返信（成功は流さない） |
| Pages 公開（`pages.yml`）成功 | 公開に含まれた PR それぞれのスレッドに「サイトに公開されました」と返信。前回の公開成功以降にマージされた PR を全部探し、「同時に公開: #x」も添える |

### 毎朝のまとめ

- 毎朝 8:00（日本時間）に、フォーラム内の固定の投稿「**毎朝のまとめ**」（ピン留め）に返信する。初回に自動で作る。
- 内容: 未マージの PR（スケジュールタスクか・ドラフト・要検討・スレッドへのリンク）と、未解決の Issue。
- 最終更新から **3 日**以上動きのない PR は強調し、1 件でもあればメンションする（放置 PR のリマインドを兼ねる）。
- PR も Issue も無い日は投稿しない。
- GitHub の定期実行は混雑で数分〜数十分遅れることがある。

## 設定値（`discord_notify.py` 冒頭）

| 定数 | 値 | 意味 |
|---|---|---|
| `DISCUSS_LABEL` | `needs-discussion` | メンション＋Discord のタグ `要検討` の対象にする GitHub ラベル |
| `SCHEDULE_LABEL` | `event` | スケジュールタスクの PR に付くラベル |
| `STALE_DAYS` | `3` | まとめで「放置」と強調する日数 |
| `DIGEST_THREAD_NAME` | `毎朝のまとめ` | まとめを投稿する固定の投稿の名前 |
| `TAG_*` | `スケジュール` `要検討` `マージ済み` `クローズ` | フォーラムのタグ名（Discord 側と同じ名前にする。無いタグは無視して警告を出す） |

## 準備（Discord / GitHub 側）

1. Discord Developer Portal（https://discord.com/developers/applications）で Bot を作り、トークンを発行する。
2. OAuth2 → URL Generator で `bot` と権限（メッセージの送信・スレッドでメッセージを送信・リアクションの追加・スレッドの管理・メッセージ履歴を読む・リンクを埋め込む）を選び、生成された URL でサーバーに追加する。
3. フォーラムチャンネルを作り、タグ `スケジュール` `要検討` `マージ済み` `クローズ` を登録する。
4. リポジトリの Settings → Secrets and variables → Actions に登録する。

| Secret | 中身 |
|---|---|
| `DISCORD_BOT_TOKEN` | Bot のトークン |
| `DISCORD_FORUM_CHANNEL_ID` | フォーラムチャンネルの ID（開発者モードで右クリック →「チャンネル ID をコピー」） |
| `DISCORD_MENTION_USER_ID` | メンションする自分のユーザー ID（任意。無ければメンションしない） |

`DISCORD_BOT_TOKEN` か `DISCORD_FORUM_CHANNEL_ID` が無いときは、警告を出して何もしない（失敗にはしない）。

## 手動実行・動作確認

- Actions → **Discord notify** → Run workflow
  - `pr` に PR 番号を入れる → その PR のスレッドを作る（あればタグ・リアクションを同期）
  - 空のまま → 毎朝のまとめを今すぐ投稿
- ローカルで送る内容だけ確認する（Discord / GitHub には書き込まない）:

```bash
GITHUB_TOKEN=$(gh auth token) DRY_RUN=1 DISCORD_FORUM_CHANNEL_ID=FORUM GITHUB_EVENT_NAME=schedule GITHUB_EVENT_PATH=event.json python -X utf8 .github/scripts/discord_notify.py
```

## 制約

- `pull_request_target` / `workflow_run` / `schedule` は **main にあるワークフロー定義**で動く。このファイルを変えても、main にマージされるまで反映されない。
- フォークからの PR へのレビューでは GitHub がシークレットを渡さないため、レビュー通知は届かない（コメントは届く）。
- Claude Code のセッションや Auto-fix が自分のアカウントで書いたコメントは「人のコメント」として流れる（ボット判定できない）。
- 同じ PR の出来事は `concurrency` で順番に処理する。短時間に 3 件以上重なると、待機中の 1 件が GitHub に取り消されることがある（タグは次の出来事で同期される）。
